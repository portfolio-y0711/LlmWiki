## 📝 1. 영상 전체 요약

> Anthropic이 수백 개의 내부 Claude Code 스킬을 운영하면서 발견한 핵심 원칙들을 공개한 내용으로, 스킬은 마크다운 파일이 아닌 폴더 구조로 설계해야 하고, Gotchas(반복 실패 기록) 섹션이 가장 가치 있으며, Description은 요약이 아닌 트리거 조건으로 작성하고, 온디맨드 훅으로 상황별 모드를 구현할 수 있다는 실전 가이드를 제공한다.

---

## 📖 2. 영상 주요 주제 (추상화된 목차)

*   **[스킬의 구조 재정의: 파일이 아닌 폴더]**

    - **세부 주제:** 일반적 오해: 스킬 = 마크다운 파일 하나에 지시문 작성. Anthropic 내부 잘 작동하는 스킬의 실제 구조: `SKILL.md`(메인 지시문) + `references/`(API 문서·코드 스니펫) + `scripts/`(검증 스크립트) + `sfs/`(템플릿)
    - **세부 주제:** 비유: 마크다운 파일 하나 = 레시피만 있는 요리법 vs. 폴더 구조 = 재료·도구·레시피 모두 포함된 밀키트. Claude가 폴더를 탐색하며 필요한 파일을 스스로 읽음 → 파일 시스템 자체가 컨텍스트 엔지니어링 도구

*   **[9가지 스킬 유형 카탈로그]**

    - **세부 주제:** Anthropic 내부 수백 개 스킬을 9가지 패턴으로 분류. "좋은 스킬은 딱 하나의 유형에 깔끔하게 들어맞고, 나쁜 스킬은 여러 유형에 걸쳐 있다"
    - **세부 주제:** 9가지 유형: ① 라이브러리 레퍼런스(내부 라이브러리 사용법·함정), ② 제품 검증(Playwright 등 자동화 테스트), ③ 데이터 조회(모니터링·분석 스택 연결), ④ 비즈니스 자동화(스탠드업·위클리 리캡 등 반복 업무), ⑤ 코드 스캐폴딩(보일러플레이트 자동 생성), ⑥ 코드 리뷰(스타일 강제·자동 리뷰), ⑦ CI/CD(PR 모니터링·자동 롤백), ⑧ 런북(장애 알림 시 자동 조사·보고서 생성), ⑨ 인프라 운영(불필요 리소스 정리·비용 분석)

*   **[스킬 콘텐츠 작성 원칙: Gotchas 섹션]**

    - **세부 주제:** "뻔한 말 하지 마라(Don't state the obvious)": Claude는 코딩을 이미 잘 안다. 스킬에는 Claude가 추론으로 절대 알 수 없는 것만 작성 — 조직만 아는 규칙, 코드베이스의 함정. 예: "우리 빌딩 립은 이 함수 호출 전에 반드시 tenant_id를 먼저 설정해야 한다"
    - **세부 주제:** Anthropic 내부 사례: 프론트엔드 디자인 스킬에 "Inter 폰트 쓰지 마, 보라색 그라데이션 쓰지 마" 추가 — Claude의 기본 성향을 깨는 정보
    - **세부 주제:** Gotchas 섹션 = 스킬에서 가장 높은 가치를 가진 콘텐츠. Claude가 반복적으로 실패하는 지점을 모은 목록. 신입 사원 매뉴얼보다 선배가 귀에 대고 알려주는 "이건 절대 이렇게 하면 안 돼" 목록
    - **세부 주제:** 점진적 개선 원칙: "대부분의 스킬이 몇 줄과 하나의 Gotcha로 시작해서 사람들이 계속 추가하면서 좋아졌다." 처음부터 완벽한 스킬 만들지 말고 실패할 때마다 한 줄씩 추가. 스킬은 한 번 쓰고 끝나는 문서가 아닌 살아있는 시스템

*   **[점진적 공개와 Description 트리거 조건]**

    - **세부 주제:** 점진적 공개(Progressive Disclosure): 스킬 MD 하나에 모든 정보를 넣으면 컨텍스트 폭발. 메인 파일에는 개요와 파일 목록만, 상세 내용은 별도 파일로 분리(API 시그니처 → references/api.md, 출력 템플릿 → sfs/template.md). Claude가 필요할 때만 해당 파일을 스스로 읽음
    - **세부 주제:** Description 함정: 대부분이 "배포 관련 스킬" 같은 요약으로 작성 → Claude가 언제 써야 할지 판단 못함. 올바른 작성: "사용자가 서비스를 프로덕션에 배포하려 하거나 PR 머지 후 배포 상태를 확인하려 할 때 사용한다" → Description은 사람이 읽는 요약이 아닌 Claude가 읽는 트리거 조건

*   **[헬퍼 스크립트와 온디맨드 훅]**

    - **세부 주제:** 헬퍼 스크립트: scripts/ 폴더에 미리 만든 함수 라이브러리 제공 → Claude가 보일러플레이트를 매번 새로 짜는 대신 조합에 집중. 예: 데이터 분석 스킬에 이벤트 조회 함수·코호트 비교 함수 사전 제공
    - **세부 주제:** 온디맨드 훅(On-Demand Hooks): 스킬 호출 시에만 켜지고 세션 종료 시 자동으로 꺼지는 검문소. `/careful` 스킬: 배시 명령 실행 전 자동 검사(rm -rf 차단, DROP TABLE 차단, git push --force 차단). `/freeze` 스킬: 특정 폴더 외 수정 잠금(디버깅 중 다른 파일 수정 방지)
    - **세부 주제:** 온디맨드 훅의 의미: 에이전트에게 모드를 부여. 평소 = 자유 모드, 위험한 작업 = 안전 모드, 디버깅 = 동결 모드. 필요한 순간에만 가드레일을 올렸다 내렸다

*   **[팀 공유: 플러그인 마켓플레이스 방식]**

    - **세부 주제:** 소규모 팀: 레포의 `.claude/skills/` 폴더에 추가 → 팀원 모두 같은 스킬 사용
    - **세부 주제:** 대규모 팀: 스킬이 많아지면 컨텍스트 점유 문제 발생 → 플러그인 마켓플레이스 방식. Anthropic 내부 운영: 누구나 샌드박스에 업로드 → Slack에서 홍보 → 실제 많이 쓰이면 공식 마켓에 등록. 중앙 관리가 아닌 자연스러운 품질 경쟁 구조

*(참고: 이 항목은 영상의 논리적 구조를 추상화하여 그룹화한 것이며, 시간 정보는 포함되지 않습니다.)*

## ⏳ 3. 주요 시간대별 상세 요약

*   **[00:00:00] ~ 도입: 스킬이 말을 안 듣는 이유**

    - 공통 불만: 마크다운 스킬 파일을 만들었는데 처음엔 되다가 점점 지시를 따르지 않음
    - 핵심 질문: Anthropic 내부에서 수백 개의 스킬을 운영하면서 발견한 것이 무엇인가? 그것을 공개

*   **[00:01:30] ~ 스킬은 폴더다**

    - Anthropic 내부에서 잘 작동하는 스킬의 실제 구조: `SKILL.md` + `references/`(API 문서, 코드 스니펫) + `scripts/`(검증 스크립트) + `sfs/`(템플릿)
    - Claude는 폴더를 탐색하며 필요한 파일을 스스로 읽음: "API 호출 코드 짜야겠다 → references/ 읽어봐야겠다"
    - 비유: 마크다운 파일 = 레시피만 있는 요리법 vs. 폴더 구조 = 밀키트(재료+도구+레시피 포함)

*   **[00:03:00] ~ 9가지 스킬 유형**

    - Anthropic 내부 수백 개 스킬 카탈로그화 결과 9가지 패턴
    - ① 라이브러리 레퍼런스, ② 제품 검증(엔지니어 1주일 투자해 완벽한 검증 스킬 제작), ③ 데이터 조회, ④ 비즈니스 자동화(매일 GitHub 활동 모아 스탠드업 작성), ⑤ 코드 스캐폴딩, ⑥ 코드 리뷰, ⑦ CI/CD, ⑧ 런북, ⑨ 인프라 운영
    - 활용법: 체크리스트로 "우리 팀에 아직 없는 유형이 뭐지?" 점검

*   **[00:05:30] ~ 뻔한 말 하지 마라 + Gotchas**

    - 잘못된 스킬 작성: "Python으로 API 호출하는 법" → Claude가 이미 안다. 쓸 필요 없음
    - 올바른 내용: "우리 빌딩 립은 이 함수 호출 전에 반드시 tenant_id를 먼저 설정해야 한다" → Claude가 추론으로 알 수 없는 것
    - Anthropic 내부 사례: 프론트엔드 디자인 스킬에 "Inter 폰트 쓰지 마, 보라색 그라데이션 쓰지 마" 추가 — "Claude스러운 디자인" 방지
    - Gotchas 섹션 = 스킬에서 가장 가치 있는 콘텐츠. Claude가 반복적으로 실패하는 지점 목록. 실패할 때마다 하나씩 추가

*   **[00:08:00] ~ 점진적 개선: 완벽한 스킬을 만들려 하지 마라**

    - "대부분의 스킬이 몇 줄과 하나의 Gotcha로 시작해서 사람들이 계속 추가하면서 좋아졌다"
    - 스킬은 한 번 쓰고 끝나는 문서가 아닌 살아있는 시스템. 에이전트의 실패를 관찰하면서 경험치를 코딩하는 것

*   **[00:09:00] ~ 점진적 공개**

    - 모든 정보를 스킬 MD 하나에 집어넣으면 컨텍스트 폭발
    - 메인 파일에는 개요와 파일 목록만. 상세 내용은 하위 파일로 분리
    - 스킬 MD에 "이 폴더에 이런 파일들이 있다"만 써놓으면 Claude가 필요할 때 스스로 해당 파일 읽음
    - 밀키트 비유: 상자 겉면에 "안에 고기·양념·채소 있다" → 요리사가 필요한 것만 꺼냄

*   **[00:10:30] ~ Description은 트리거 조건**

    - 문제: "배포 관련 스킬"처럼 요약으로 작성 → Claude가 언제 써야 할지 판단 못함
    - Claude Code 동작: 세션 시작 시 모든 스킬의 Description을 스캔 후 요청에 맞는 스킬 판단
    - 올바른 작성: "사용자가 서비스를 프로덕션에 배포하려 하거나 PR 머지 후 배포 상태를 확인하려 할 때 사용한다"
    - 스킬을 만들었는데 Claude가 안 쓴다면 → Description부터 확인

*   **[00:12:00] ~ 헬퍼 스크립트와 온디맨드 훅**

    - 헬퍼 스크립트: scripts/ 폴더에 미리 만든 함수 제공 → Claude가 보일러플레이트 재작성 없이 조합에 집중
    - 온디맨드 훅: 스킬 호출 시에만 켜지는 검문소
      - `/careful`: rm -rf·DROP TABLE·git push --force 자동 차단. 프로덕션 작업 시 안전 모드
      - `/freeze`: 특정 폴더 외 수정 잠금. 디버깅 중 다른 파일 수정 방지
    - 에이전트에게 상황별 모드 부여: 평소(자유 모드) → 위험한 작업(안전 모드) → 디버깅(동결 모드)

*   **[00:14:00] ~ 팀 공유: 플러그인 마켓플레이스**

    - 소규모 팀: `.claude/skills/` 폴더에 추가
    - 대규모 팀: 스킬 증가 → 컨텍스트 점유 문제 → 플러그인 마켓플레이스. Anthropic 내부: 샌드박스 업로드 → Slack 홍보 → 많이 쓰이면 공식 마켓 등록
    - 결론: 스킬 = 폴더, Gotchas 기록, Description = 트리거 조건, 점진적 공개, 온디맨드 훅으로 모드 구현. 처음부터 완벽하게 만들려 하지 말고 실패마다 한 줄씩 추가

*(이후 영상 끝까지 중요한 흐름이 바뀔 때마다 시간대별 요약 추가)*
