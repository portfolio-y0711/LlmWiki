# Codex 완벽 가이드 2026: 지금은 코덱스가 최강인 것 같네요.

여러분 오늘은 OpenAI Codex에 대해서
다뤄볼 건데요. 여러분들께서
Claude Code 말고 Codex도 다뤄 달라고
많이들 요청을 주셨는데 어 드디어
OpenAI Codex 영상을 준비해서
왔습니다. 어 그래서 이번 영상에서는
Codex의 기본적인 사용 방법들이나
여러분들이 기존에 Codex를 사용하고
계셨다고 하더라도 잘 알지 못하는
여러 가지 꿀팁들도 많이 준비를
했으니까 영상 끝까지
잘 시청해 주시면 감사할 것 같습니다.
어, Codex를 다루기 전에 최근에 이
Claude Code 여러분들이 기존에 사용하던
Claude Code가 뭔가 답답하다라고
느끼셨던 분들도 많을 것 같습니다.
어, 그런데 이틀 전에 Anthropic에서
Claude Code의 품질이 낮아진 게
맞다라고 하는 이런 공식적인
어, 발표를 하기도 했었는데요.
어, 그래서 이제 세 가지의 주요 원인이
있었고 첫 번째로는 Claude Code의
기본 추론 난이도가 원래는 높음으로
되어 있었는데 이게 중간으로 변경이
되었던 이런 문제가 있었고요. 그래서
Claude Code가 기본적으로 동작을 할 때
이 추론 단계가 낮아짐으로써 어 이
Claude 모델이 좀 바보같이 느껴지는
부분이 있었다고 하고요. 그래서
이거는 지금은 원상 복구가 완료가
되었다라고 합니다. 그리고 이제
두 번째로는 Claude Code의 캐싱 문제가
있었는데 어 한 시간 이상 활동이 없던
세션에서 Claude Code 이전 사고
과정을 어 지우는 변경 사항을 이렇게
적용을 했다라고 하고요. 그래서
기존에 있는 사항이 지워지니까
Claude가 기억을 잘 못 하고 말을
반복하는 것처럼 보이는 이런 현상들도
나타났다라고 합니다. 어, 그리고
세 번째는 Claude Code의 출력량을 줄이기
위해서 이 시스템 프롬프트 지침이
업데이트가 되었다라고 했는데 이것도
이제 기존에 있는 다른 프롬프트의
변경 사항이랑 맞물려 가지고 코드
품질에 부정적인 영향을 미쳤다라고
이렇게 하고 있습니다. 그래서
전체적으로 요번에 발생한 이 세 가지
문제점을 봤을 때 Claude Code의
비용을 좀 절감하려고 했던 시도들에
있어서 Claude Code의 품질이 낮아지게
되었다라고 그렇게 보여지는 것
같습니다. 뭐 여러 가지로 문제점들이
많아져서 Claude Code를 사용하던
개발자들이 Codex로 점점점 넘어가고
있는 추세로 보여지는 거 같은데요.
그래서 이번 영상에서도 여러분들이
Codex를 처음 사용하시는 분들도 아마
많으실 것 같아서 Codex는
Claude Code와 어떤 부분이 다르고 어떤
강점들이 있는지에 대해서 한번 말씀을
드려 보도록 하겠습니다. 어, 일단은
최근에 이제 OpenAI 쪽에서도 굉장히
많은 업데이트가 있었죠. 그리고
첫 번째로는 이렇게 이미지 2.0이라고
하는 게 새로 나오게 되면서 이미지
생성 능력이 굉장히 많이 좋아지게
되었다라고 합니다. 그래서 제가 이제
몇 가지 이미지를 생성하는 것을
테스트를 해 봤는데 그래서 뭐 요런
이미지가 생성이 되었습니다. 이게
이게 스크린샷을 찍은 게 아니고 실제로
이미지 생성을 통해서 생성된
이미지잖아요. 이렇게 브라우저를
띄워서 ChatGPT에서 이렇게 프롬프트들
입력하는 요런 장면을 어 이미지
생성으로 이렇게 만들어 낸 거 굉장히
사실적이죠. 그리고 두 번째로는
이렇게 과학 대중 잡지를 생성해
달라라고 그렇게 요청을 했습니다.
요것도 이제 보시면은 한글 잡지를
생성해 달라고 했거든요. 근데 이 한글
표현력을 한번 보세요. 원래 이제
이미지 생성의 가장 큰 문제점 중에
하나가 이런 한글 같은 거를
잘 생성을 못 해 주는 게
문제점이었잖아요. 근데 요번에 이미지
2.0에서는 이렇게 한글도 거의
완벽하게 잘 생성을 해 주는 모습을
확인할 수가 있고 굉장히 놀라운 거
같습니다. 이런 식으로 한글로 손
글씨를 작성한 것들도 엄청나게 잘
생성을 해 주고 어 그리고 이렇게 제
프로필 사진 하나 넣고
퍼스널 컬러 분석 보고서 이미지를
생성해 달라고 이렇게 요청했더니
이런 식으로 퍼스널 컬러 분석
보고서 같은 경우도 어 굉장히
잘 만들어 줍니다. 어 지금까지
있던 이미지 생성 모델 대비해서
엄청난 퀄리티의 이미지 생성
능력을 보여 주는 것 같습니다.
그래서 오늘 Codex CLI에서
이미지 생성 기능을 다루는 방법들도
같이 다뤄 보도록 하겠습니다.
그리고 이틀 전에 GPT-5.5 모델도
새로 나왔는데 요것도 이제
성능이 굉장히 많이 좋아졌거든요.
그래서 Codex를 사용하기에
굉장히 좋은 시점이 아닌가라고
생각이 드는 것 같고요.
어 Codex 설치는 이런 식으로 npm을
사용해서 Codex를 설치해 주실 수가
있고요. 어 그리고 이제 터미널에서
바로 이제 Codex를 한번
실행을 시켜 보도록 하겠습니다.
Codex 실행 명령은 이렇게
codex라고 하는 명령으로 입력을 해 주시면 되고
어 실행하시면 이런 식으로
뭐 Claude Code와 거의 비슷한 UI가
나오게 됩니다. 어, 첫 번째로는
이제 Codex의 권한을 설정할 수 있는
/permissions 명령어를
말씀드려 보도록 할 건데 Codex에서
사용할 수 있는 명령어들은 이렇게 슬래시를
입력하게 되면은 여러 가지 명령어들을
이렇게 확인을 하실 수가 있습니다.
그중에서 이제 /permissions라고
하는 명령어를 입력해서 들어와 주시면
이렇게 Codex에는 크게 세 가지 모드가
있다라고 보시면 되고요.
가장 기본적인 모드는 Codex가 이제
파일 읽기와 수정 같은 것은
자유롭게 진행을 하되 외부 인터넷으로
액세스를 하거나 현재 디렉토리
외부에 있는 파일을 수정하는 경우는
사용자의 승인을 받고 할 수 있게
해 주는 모드가 어 기본 모드로
되어 있을 겁니다. 그리고 두 번째는
이제 오토 리뷰라고 하는
모드가 있는데요. 이 오토 리뷰라고 하는
모드는 디폴트 모드보다는 조금 더
자율적으로 동작을 하게 해주되
Codex 자체적으로 이제
오토 리뷰어라고 하는 서브 에이전트를
돌려 가지고 여러분들이 어떤 명령을
실행했을 때 그 명령어가 에이전트가
판단하기 안전한 명령어인지
아니면 사용자에게 한번 물어보고
실행을 해야 되는 그런 명령어인지를
파악을 하게 해 주는 그런 모드가
어 오토 리뷰 모드라고
볼 수가 있습니다. 그리고 이제 세 번째로는
이제 풀 액세스 모드가 있는데
요건 이제 제로 모드라고 보시면
됩니다. 그래서 에이전트가 모든
명령을 알아서 자율적으로 실행해 줄 수
있게 해 주는 모드가 이렇게
풀 액세스 모드가 있고요. 그래서
여러분들이 여기서 이제 원하는 모드를
선택해서 활용을 해 주시면 되고
그리고 Codex를 사용할 때
이 채팅창 아래에 있는 이 스테이터스
라인도 설정을 해 줄 수가 있습니다.
스테이터스 라인을 설정하는 방법은
/statusline이라고 하는 명령을
입력해 주시게 되면은 여기서
여러분들이 원하는 것을 이렇게
활성화하고 비활성화할 수 있게
만들어 줄 수가 있는데요.
저 같은 경우는 이제 첫 번째로
이제 모델명과 reasoning 단계
그리고 git 브랜치 컨텍스트를
얼마나 사용했는지 패스트 모드가
켜져 있는지 아닌지 그리고 현재
프로젝트 이름 뭐 요런 것들을
이제 설정을 해 두고 이렇게
활용을 하고 있습니다. 그래서
여러분들도 여기서 원하는 것을
이렇게 활성을 해서 엔터를
눌러 가지고 설정을 해 주시면은
될 거 같습니다. 이제 첫 번째로
Codex에게 명령을 한번 날려
보도록 할 건데요. 현재 코드 분석해 줘라고
이런 식으로 그냥 채팅을 날려 가지고
명령어를 작성해 주시면은 되고요.
작업을 미리 예약을 해 두고
싶다라고 하면은 이렇게 프롬프트를
작성한 다음에 Tab 키를 눌러 주게 되면은
이거는 이제 기존 작업에는 영향이 가지 않고
이렇게 후속 작업으로 큐에 쌓이게 됩니다.
어 이거는 큐에 쌓이는 것들은
여러분들이 몇 개든 상관없이
계속해서 큐에다가 쌓아 놓을 수가 있고요.
가끔 이렇게 긴 시간 동안
작업을 하는 와중에 뭔가 다음 작업에
대해서 미리 예약을 해 두고 싶을 때
이렇게 Tab 키를 통해서 프롬프트를
날려서 큐에다가 넣어 놓을 수 있는
이런 방식들도 활용을 하시면은
좋을 것 같습니다. 자, 그리고
이런 식으로 이제 분석 결과가
이렇게 나오게 되었는데요. 요 분석 결과를
만약에 나는 복사해 가지고
다른 세션의 Codex에서 활용하고 싶다.
아니면은 뭐 Claude Code에서
활용하고 싶다. 이거를 가지고
뭔가 문서를 생성하고 싶다라고 했을 때
Codex는 이 /copy라고 하는 명령어가 있습니다.
이 /copy라고 하는 명령어를 활용하면은
마지막 응답 결과를 클립보드에
복사해 줄 수가 있는 기능이라고
보시면 되는데요. 그래서
이렇게 /copy라고 하는 명령을 입력하고
엔터를 눌러 주셔도 되고요.
아니면은 단축키로
Ctrl+O라고 하는 단축키를 눌러 주시면
그럼 이렇게 마지막 메시지가
여러분들의 클립보드에 복사가 된다라고
보시면 될 거 같습니다.
그래서 이렇게 클립보드에 복사
메시지를 여러분들이 원하는 어떤
에디터에다가 이렇게 붙여 넣고
이런 식으로 확인도 해 주실 수가
있습니다. 그리고 이제 /clear라고
하는 명령어가 있는데요.
이 /clear라고 하는 명령어는 기존에 대화
내역을 완전히 초기화해 버리고
완전히 새로운 세션에서 새롭게 작업을
해 줄 수 있게 하는 명령어가
/clear라고 보시면 되고요. 그래서
지금 우리가 해당 세션에서 이렇게
31%의 컨텍스트를 사용하게 되었는데
이 컨텍스트 사용량이 많아지면 많아질수록
에이전트의 성능이 떨어질 수밖에
없거든요. 그렇기 때문에 우리가
필요한 경우 이렇게 주기적으로
/clear라고 하는 명령어를 사용해서
이렇게 컨텍스트를 다시 0%로
초기화를 시켜 주는 작업이
필요합니다. 제가 이제 권장드리는
방법은 이 하나의 세션에서 계속해서
대화를 이어 나가시는 것보다는
맥락이 이어지는 기능 단위별로 세션을
계속해서 새로 생성해 가지고
작업을 해 주시는 게 더 좋은 방식이라고
생각이 되고요. 그래서 저는 이제
/clear 명령을 이렇게 주기적으로
활용하면서 컨텍스트를 최적화시키고
작업을 하는 것을 좀 선호하고
있습니다. 그리고 이제 프롬프트를
작성을 할 때 기존에 이전에
작성했던 프롬프트를 다시 한번
사용하고 싶을 때가 있잖아요. 그럴 때는
이제 위아래 방향키를 통해서 이렇게
기존에 작성했던 프롬프트의 목록을
확인을 하실 수도 있고요. 또는 특정
프롬프트를 검색을 해서 찾아보고
싶다라고 할 수도 있는데 그럴 때는
이렇게 Ctrl+R 키를 눌러 주게 되면
이렇게 프롬프트를 검색할 수 있는
기능이 활성화가 되게 되고 여기다가
이제 이런 식으로 여러분들이
원하는 프롬프트에 대해서 검색을 하게
되면은 프롬프트 히스토리에서 이렇게
검색도 할 수가 있습니다. 그래서
Ctrl+R을 누르면 이렇게 프롬프트를
검색할 수 있는 기능도 있다라고 하는
부분도 기억을 해 주시면은
좋을 것 같습니다. 그리고 이제 Codex에서
작업하다 보면은 이 프롬프트를
잠시 임시 저장을 해 두고 다른 작업을
하고 다시 돌아와서 이 프롬프트를
이어서 작성하고 싶을 때가 있거든요.
그럴 때 보통 이런 프롬프트를 이렇게
복사해 가지고 잠깐 메모장에 적어
두고 작업을 할 수도 있지만
어 Codex에서 이제 Ctrl+C를 누르게 되면
이렇게 기존에 작성했던
프롬프트가 전체 삭제되게 됩니다.
그리고 그렇게 작성했던 프롬프트는
프롬프트 히스토리에 저장이 되기 때문에
이제 방향 키를 통해서 이렇게
위로 올려 주시면 기존에 작성했던
프롬프트를 이렇게 다시 돌려 가지고
작업을 이어나갈 수도 있습니다.
Claude Code에서는 이 기능을
ESC 키를 눌러 가지고 활용이 가능했었는데
어 Codex에서 이렇게 ESC 키를 눌러도
아무런 아무런 반응을 하지 않거든요.
