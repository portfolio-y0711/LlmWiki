## 📝 1. 영상 전체 요약

> 수만 명이 극찬한 `/grill-me` 스킬의 한계 — 세션마다 도메인 용어를 재설명해야 하는 비효율 — 를 Domain-Driven Design의 **유비쿼터스 언어(Ubiquitous Language)** 개념으로 해결한 신규 스킬 **`/grill-with-docs`**를 소개한다. Grill Me에 `context.md`(공유 언어 문서)와 ADR(아키텍처 결정 기록)을 결합하여, AI와의 소통 효율을 근본적으로 향상시키는 방법을 실전 데모와 함께 설명한다.

## 📖 2. 영상 주요 주제 (추상화된 목차)

*   **도입 — Grill Me의 한계 발견**

    - **세부 주제:** Grill Me 스킬의 성공 — 4문장으로 설계된 인터뷰 스킬이 커뮤니티에서 폭발적 반응을 얻음
    - **세부 주제:** 반복적인 도메인 용어 재설명 문제 — 세션마다 "standalone video"가 무엇인지, 각 엔티티가 무엇인지 에이전트에게 다시 설명해야 하는 비효율

*   **핵심 개념 — 유비쿼터스 언어와 context.md**

    - **세부 주제:** Domain-Driven Design의 유비쿼터스 언어 — 개발자·도메인 전문가·코드가 동일한 언어를 공유해야 한다는 Eric Evans의 개념
    - **세부 주제:** `context.md` 파일 — 코드베이스의 공유 언어(엔티티·용어·관계)를 문서화한 단일 파일; Bounded Context 단위로 여러 개 사용 가능
    - **세부 주제:** ADR(Architectural Decision Record) — 맥락 없이는 이해하기 어려운 비자명한 결정들을 마크다운으로 기록하는 문서

*   **심화 활용 — Grill with Docs 실전 데모**

    - **세부 주제:** 첫 실행 시 context.md에서 기존 용어를 자동 감지하고 언어 충돌·카디널리티 문제를 우선 해결하는 흐름
    - **세부 주제:** 그릴링 중 context.md를 실시간으로 업데이트 — 새로 합의된 언어가 즉시 문서에 반영되어 이후 세션에서 재사용
    - **세부 주제:** 유비쿼터스 언어 정립의 3가지 실용적 이점 — 간결한 응답, 사고 트레이스(thinking trace) 효율화, 코드 탐색 용이성

*   **결론 — Grill Me vs Grill with Docs 사용 기준**

    - **세부 주제:** Grill Me의 새로운 위치 — 코드베이스 없는 일반 용도(기획·글쓰기·추모사 작성 등)에 최적화된 생산성 스킬로 재분류
    - **세부 주제:** 사용 규칙 — 코드베이스가 있으면 `Grill with Docs`, 없으면 `Grill Me`

*(참고: 이 항목은 영상의 논리적 구조를 추상화하여 그룹화한 것이며, 시간 정보는 포함되지 않습니다.)*

## ⏳ 3. 주요 시간대별 상세 요약

*   **[00:00:00] ~ Grill Me의 성공과 새로운 불만**

    - Grill Me 스킬: 4문장으로 설계, AI가 공유 이해에 도달할 때까지 인터뷰를 지속하는 방식
    - 커뮤니티 반응: "절대적인 게임체인저", "일을 느리게 만드는 줄 알았는데 결국 시간을 절약해줌"
    - 불만 발견: 세션마다 "standalone video"처럼 비자명한 도메인 용어를 재설명해야 하는 반복 작업
    - 질문: **"AI에게 최소한의 추가 컨텍스트를 제공하는 가장 얇은 문서 레이어가 무엇일까?"**



*   **[00:03:00] ~ 유비쿼터스 언어 개념 도입**

    - Eric Evans의 Domain-Driven Design(DDD)에서 차용한 개념
    - **유비쿼터스 언어**: 개발자(How to build) + 도메인 전문가(What to build) + 코드가 동일한 언어를 사용해야 함
    - 기존 접근: Grill Me + 별도 Ubiquitous Language 스킬을 병행 사용 → 불편
    - 해결: 두 스킬을 통합한 **`/grill-with-docs`** 스킬 탄생



*   **[00:05:00] ~ Grill with Docs 스킬 설계**

    - Grill Me의 핵심 인터뷰 로직 + 두 가지 추가 레이어:
      1. **`context.md` 통합**: 기존 공유 언어 문서를 자동으로 읽어 세션 시작 전 참조
         - 언어 사용을 기존 글로서리에 대조 검증
         - 모호한 언어 샤프닝(fuzzy language sharpening)
         - 구체적 시나리오 논의 및 코드 교차 참조
         - 세션 중 실시간 업데이트
      2. **ADR(Architectural Decision Record) 생성**: 비자명하고(hard to reverse) 이유 없이는 놀랍게 보이는 결정들을 별도 마크다운 파일로 기록
    - `CLAUDE.md` 로컬 파일에 `context.md` 위치 포인터 추가



*   **[00:08:00] ~ 실전 데모 — "Pitches" 피처 그릴링**

    - 새 엔티티 "Pitch" 추가 요구사항: Mr. Beast 방식 — 영상 제작 전 패키징(제목·설명·프레이밍)을 먼저 기획하는 개념
    - Grill with Docs 첫 반응: context.md에서 "standalone video" 감지 → 즉시 언어 문제 우선 해결
    - 세션에서 해결된 핵심 언어 문제들:
      - **카디널리티**: Pitch ↔ Standalone Video = 1:N 관계
      - **용어 충돌**: "standalone video"가 pitched/unpitched 모두를 포함해야 하는지 → Pitch를 Standalone Video의 메타데이터로 처리 결정
      - **상태 시맨틱**: Pitch의 상태(idle/scheduled/shipped) → 자유 전환 방식 채택
      - **삭제 정책**: ON DELETE RESTRICT (삭제 대신 아카이빙 선호)
    - 세션 중 context.md에 Pitch·Pitch Status·Standalone Video 정의 즉시 반영



*   **[00:13:00] ~ 유비쿼터스 언어의 3가지 실용적 이점**

    - **①  간결한 응답**: 공유 언어 덕분에 AI가 용어를 장황하게 재설명하지 않아도 됨 → 응답 토큰 절약
    - **② 사고 트레이스 효율화**: AI는 언어로 내부 추론을 수행함 → 공유 언어가 있으면 AI의 추론 과정 자체도 더 정확하고 간결해짐
    - **③ 코드 탐색 용이성**: 코드 파일명·변수명이 context.md의 언어와 일치 → "pitches 관련 코드를 찾아"라는 단순 요청으로 정확한 파일 탐색 가능
    - 결론: DDD에서 인간 팀 간에 효과적인 기법이 AI 협업에서도 동일하게 작동함



*   **[00:15:00] ~ Grill Me의 재정립과 사용 가이드라인**

    - **Grill Me는 사라지지 않음** — 코드베이스 없는 일반 용도로 재분류(productivity 폴더)
    - 실제 사례: 커뮤니티 멤버가 어머니 추모사 작성에 Grill Me를 사용하여 소중한 추억들을 끌어냄
    - **최종 사용 규칙**:
      - **코드베이스가 있는 경우** → `/grill-with-docs`
      - **코드베이스가 없는 경우** → `/grill-me`
    - 프로젝트 초기(언어가 아직 정립되지 않은 시점)에도 Grill with Docs 추천 — 공유 언어를 처음부터 확립하는 것이 훨씬 유리
