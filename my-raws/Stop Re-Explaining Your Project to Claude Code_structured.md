## 📝 1. 영상 전체 요약

> Claude Code 세션이 종료되면 컨텍스트가 사라지고 매번 프로젝트 배경을 재설명해야 하는 비효율을 해결하는 세 가지 방법 — **세션 파일**, **Obsidian 대시보드(동적 메모리)**, **핸드오프 프롬프트** — 을 소개한다. 이를 통해 여러 세션·여러 날에 걸쳐 작업 흐름을 유지하고, 컨텍스트 창이 가득 찼을 때도 손실 없이 새 세션으로 이어갈 수 있다.

## 📖 2. 영상 주요 주제 (추상화된 목차)

*   **문제 인식 — Claude Code 컨텍스트 손실 문제**

    - **세부 주제:** 세션마다 5~15분을 소비하는 컨텍스트 재구성 문제 — 어떤 파일을 만들었는지, 어떤 결정이 내려졌는지 매번 설명해야 하는 반복 작업
    - **세부 주제:** 컨텍스트 창이 꽉 차면 발생하는 "Dam Zone" — 200k 토큰 이후 Claude가 게을러지고 부정확해지는 현상

*   **해결책 1 — 세션 파일(Session File)로 정적 상태 추적**

    - **세부 주제:** 세션 파일의 구조 — 목표(Goal), 배경 컨텍스트, 완료 조건(Definition of Done), 진행 상황(Progress) 기록
    - **세부 주제:** 컨텍스트 창이 꽉 찰 때마다 진행 상황을 업데이트하고 새 세션으로 이관하는 워크플로우

*   **해결책 2 — Obsidian 대시보드로 동적 메모리 구현**

    - **세부 주제:** 정적 메모리(CLAUDE.md)와 동적 메모리(대시보드)의 차이 — CLAUDE.md는 변하지 않는 작업 스타일을, 대시보드는 현재 프로젝트 상태를 담음
    - **세부 주제:** Dataview/Datacore 플러그인으로 세션·계획·작업을 동적으로 집계하는 대시보드 구성
    - **세부 주제:** 대시보드 경로를 Claude에게 제공하면 쿼리를 자동 해석하여 메모리를 로드하는 동적 컨텍스트 로딩

*   **해결책 3 — 핸드오프 프롬프트로 세션 간 컨텍스트 이전**

    - **세부 주제:** `/handoff continue` vs `/handoff park` — 다음 세션으로 이어갈지, 작업을 일시 중지할지 분기하는 명령
    - **세부 주제:** 회고(Retrospective) 스킬로 세션의 실수와 교훈을 캡처하여 스킬·프롬프트에 자동 반영
    - **세부 주제:** WMAX 터미널 통합으로 에이전트가 프로그래밍 방식으로 새 세션을 자동 시작하는 자동화

*(참고: 이 항목은 영상의 논리적 구조를 추상화하여 그룹화한 것이며, 시간 정보는 포함되지 않습니다.)*

## ⏳ 3. 주요 시간대별 상세 요약

*   **[00:00:00] ~ 문제 제기 — 반복되는 컨텍스트 재설명 비효율**

    - 매 Claude Code 세션 시작 시 5~15분이 컨텍스트 구축에 낭비됨 — "어디까지 했지?", "어떤 파일 만들었지?", "어떤 결정 내렸지?" 를 매번 재설명
    - 세션을 닫으면 컨텍스트가 사라지고, 다음 날엔 처음부터 시작해야 하는 악순환 반복
    - 이 문제를 해결하는 세 가지 방법 예고: ① 세션 파일, ② Obsidian 대시보드, ③ 핸드오프 프롬프트



*   **[00:01:00] ~ 해결책 1 — 세션 파일(Session File)**

    - Claude Code 세션은 하나의 터미널 채팅 대화이며, `context` 명령으로 현재 토큰 사용량 확인 가능 (예: 200k 토큰 소비)
    - **세션 파일** = 마크다운 파일로 목표·배경·완료 조건·진행 상황을 기록하는 단일 문서
    - 컨텍스트 창이 꽉 차면 세션 파일에 진행 상황을 업데이트하고, 새 세션에 이관하여 작업 연속성 유지
    - 예시: 강좌 개발 프로젝트에서 여러 날·여러 세션에 걸쳐 진행 상황을 세션 파일로 추적



*   **[00:02:30] ~ 해결책 2 — Obsidian 대시보드와 동적 메모리**

    - 세션 파일만으로는 프로젝트 전체 상태를 담기 부족 → 대시보드(Dynamic Memory) 개념 도입
    - **정적 메모리(CLAUDE.md)**: 작업 스타일, 선호도, AI와의 상호작용 방식 등 잘 변하지 않는 정보
    - **동적 메모리(대시보드)**: 현재 작업 중인 태스크, 세션 컨텍스트, 계획 등 실시간으로 바뀌는 정보
    - Dataview/Datacore 플러그인으로 대시보드에 연결된 세션 파일·계획·참조 문서를 자동 집계
    - Claude에게 대시보드 경로를 제공하면 쿼리를 해석하여 세션·계획 테이블을 컨텍스트에 로드 → 중단했던 지점에서 바로 이어서 작업 가능



*   **[00:04:30] ~ Dam Zone — 컨텍스트 한계에서의 전략**

    - 200k 토큰을 "Dam Zone"으로 정의 — 이 이후 Claude는 게을러지고 결과를 축약·생략하는 경향
    - 소프트웨어 엔지니어링 작업은 더 엄격하게 적용 (일부는 100k 토큰 기준 사용)
    - 표준 해결법: `/compact` 명령으로 대화 요약 후 컨텍스트 확보 — 그러나 한계 존재:
      1. 세션의 학습 내용을 별도로 캡처할 수 없음
      2. 컴팩션 프롬프트를 커스터마이징할 수 없음
    - 대안: **핸드오프 명령**으로 다음 세션에 필요한 정보만 정밀 이관



*   **[00:06:00] ~ 회고(Retrospective) 스킬로 교훈 캡처**

    - 세션 종료 전 회고 스킬 실행 → Claude가 세션 내 실수·교훈을 분석 (예: 12개 수정 사항 캡처)
    - "AI 슬로프(AI Slope)" 패턴 식별 — 어떤 작업이 반복적으로 잘못되는지 파악
    - 분석 결과로 스킬·프롬프트에 적용할 변경 사항(diff) 제안 → 승인 후 자동 반영
    - 이를 통해 같은 실수를 다음 세션에서 반복하지 않아도 됨



*   **[00:07:30] ~ 핸드오프 명령 — continue vs park**

    - 회고 완료 후 컨텍스트는 23% 수준으로 줄어듦
    - `/handoff continue`: 현재 프로젝트를 다음 세션으로 이어갈 때 사용
      - 완료된 작업, 다음 단계, 다음 세션의 의도를 담은 핸드오프 파일 자동 생성
      - WMAX 터미널과 연동하여 에이전트가 프로그래밍 방식으로 새 터미널 세션 시작
      - 새 에이전트에게 핸드오프 파일 전달 → 4% 컨텍스트로 작업 재개
    - `/handoff park`: 작업을 일시 중지할 때 사용
      - Obsidian 세션 파일에 현재 진행 상황 업데이트
      - 나중에 세션 파일을 읽어 작업 재개 가능



*   **[00:09:00] ~ 마무리 및 다음 영상 예고**

    - 세 가지 방법(세션 파일·대시보드·핸드오프)으로 컨텍스트를 영구적으로 보존하는 워크플로우 완성
    - CLAUDE.md 점검 권장 — 오래된 정보는 대시보드로 이동하여 항상 최신 상태 유지
    - 다음 영상 예고: **"삶을 위한 대시보드 구축 방법"**
