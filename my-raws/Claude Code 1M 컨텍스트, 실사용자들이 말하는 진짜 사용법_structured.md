## 📝 1. 영상 전체 요약

> Claude Code 컨텍스트 윈도우가 20만에서 100만 토큰으로 확장된 3월 13일 업데이트의 실제 의미를 분석하며, 공식 발표(다섯 배 확장·가격 프리미엄 폐지·미디어 600개)와 달리 실사용자들은 이를 "100만 채우기"가 아닌 "작업 중단 없는 버퍼"로 활용하고, 이제 AI에게 기획서·디자인·구조 파일을 통째로 줄 수 있는 패러다임 전환이 진짜 이점임을 강조한다.

## 📖 2. 영상 주요 주제 (추상화된 목차)

*   **[문제 진단: 컴팩션과 느린 표류]**

    - **세부 주제:** 컴팩션(Compaction) 정의: 대화가 길어져 메모리 한계에 도달하면 AI가 앞 대화를 요약하고 나머지를 버리는 현상. 비유: 열 페이지 기획서를 줬는데 AI가 세 페이지만 읽고 나머지를 찢어버린 채 일하는 것
    - **세부 주제:** 느린 표류(Slow Drift): 컴팩션은 에러가 아님. 코드는 돌아가지만 방향이 조금씩 틀어지는 현상. 배가 침몰하는 게 아니라 모르는 사이에 목적지가 바뀌어 있는 것 — 가장 짜증나는 Claude Code 문제

*   **[3월 13일 업데이트: 공식 발표 내용]**

    - **세부 주제:** 컨텍스트 윈도우 20만 → 100만 토큰(5배 확장): 콤팩션 발생 시점이 5배 늦춰져 긴 작업을 끊김 없이 이어갈 수 있음. Max·Team·Enterprise 플랜 자동 적용, 코드 변경 불필요
    - **세부 주제:** 가격 프리미엄 폐지: 토큰 사용량에 무관하게 동일 요금. Opus 기준 입력 5달러·출력 25달러 동일
    - **세부 주제:** 미디어 한도 6배 확장: 이미지·PDF 100개 → 600개

*   **[벤치마크 vs. 실사용자 체감: 100만의 진짜 의미]**

    - **세부 주제:** Anthropic 공식 벤치마크: 긴 문서 내 정보 검색 정확도 비교. 25만(책 2권) 구간은 모든 모델 유사(Opus 4.6: 91%, GPT 5.4: 79%). 100만(책 10권)으로 늘리면 차이 극명 — Opus 4.6: 78% 유지, GPT 5.4: 36%, Gemini: 25%. "잘한다는 모델들이 무너진다"
    - **세부 주제:** Reddit 실사용자 후기: "100만 토큰은 천장이 아니라 숨 쉴 공간." 10만 토큰 증가마다 약 2% 성능 저하(절벽이 아닌 완만한 하락). 25만~50만 사이에서 체감 성능 저하 시작. 100만까지 꽉 채우면 오히려 역효과
    - **세부 주제:** 실전 전략 3가지: ① 100만을 목표로 채우지 말고 끊김 없이 끝낼 버퍼로 활용 ② 30만~40만에서 수동 컴팩션 실행 또는 새 섹션 시작 ③ 환경 변수로 자동 컴팩션 시점 조절 가능

*   **[패러다임 전환: 정보를 아낄 필요가 없어졌다]**

    - **세부 주제:** 기존 문제: 컴팩션을 두려워해 AI에게 줄 정보를 스스로 줄이던 패턴. 요약본만 주면 AI도 요약 수준의 판단밖에 못 함 — 사용자가 스스로 AI 성능을 막고 있었음
    - **세부 주제:** 컨텍스트 확장이 가져온 변화: 기획서 전문·디자인·태스크보드·이전 세션 노트·프로젝트 구조를 통째로 제공 가능 → 에이전트가 전체 맥락 기반으로 더 정확한 판단 가능
    - **세부 주제:** 트레이드오프: 컨텍스트를 많이 넣을수록 매 요청마다 전체 컨텍스트가 전송되어 구독 사용 한도 소모 가속. "정보를 아껴 엉뚱한 결과를 받고 재작업하는 것보다 충분히 주고 정확한 결과 받기가 더 효율적"

*(참고: 이 항목은 영상의 논리적 구조를 추상화하여 그룹화한 것이며, 시간 정보는 포함되지 않습니다.)*

## ⏳ 3. 주요 시간대별 상세 요약

*   **[00:00:00] ~ 도입: 컴팩션 문제와 느린 표류**

    - 공통 경험: AI에게 코드 작업 지시 시 처음엔 잘 되다가 중반부터 합의한 구조를 벗어나는 방향으로 진행
    - 원인: 컴팩션(Compaction). AI가 메모리 한계 도달 시 앞 대화를 요약하고 나머지를 삭제. 비유 — 기획서 열 페이지를 줬는데 세 페이지까지만 읽고 나머지 일곱 페이지를 찢어버린 채 일하는 것
    - 느린 표류: 컴팩션은 에러가 아니라 침묵 속 방향 이탈. 코드는 돌아가지만 목적지가 바뀌어 있음. 결과물 받아보고 나서야 "아까 합의한 거 있어 버렸네" 깨닫는 구조 — Claude Code 최대 불만 포인트

*   **[00:01:40] ~ 3월 13일 발표: 컨텍스트 5배 확장**

    - Anthropic 공식 문서: Claude Code 컨텍스트 윈도우 20만 → 100만 토큰. 콤팩션 발생 시점 5배 지연 → 복잡한 작업을 끊김 없이 이어갈 수 있음
    - 가격 프리미엄 폐지: 9,000원 구독이든 90만 원이든 추가 요금 없음. Opus 기준 입력 5달러·출력 25달러 동일
    - 미디어 한도 6배: 이미지·PDF 600개까지. Max·Team·Enterprise 플랜 자동 적용, 별도 설정 불필요

*   **[00:02:50] ~ 벤치마크: 100만에서도 정확한 모델은 하나**

    - Anthropic 공식 그래프: 긴 문서 내 정보 검색 정확도 테스트
    - 25만(책 2권) 구간: Opus 4.6 91%, GPT 5.4 79% — 모든 모델 유사
    - 100만(책 10권) 구간: Opus 4.6 78%(거의 유지), GPT 5.4 36%(반도 못 맞춤), Gemini 25%(네 개 중 하나)
    - 결론: "용량만 늘려놓고 정확하게 못 찾으면 소용없다. Opus 4.6은 커져도 정확하다. 잘한다는 모델들이 무너진다"

*   **[00:03:50] ~ Reddit 실사용자 후기: 100만의 진짜 사용법**

    - 수백 개 댓글에서 수렴된 커뮤니티 의견: "100만 토큰은 천장이 아니라 숨 쉴 공간이다"
    - 체감 데이터: 10만 토큰 증가마다 약 2% 성능 저하(절벽 아닌 완만한 하락). 25만~50만 사이에서 체감 시작. 100만까지 꽉 채우면 역효과
    - 실전 전략: ① 100만 채우기 목표가 아닌 끊김 방지 버퍼로 활용 ② 30만~40만에서 수동 컴팩션 또는 새 섹션 시작 ③ 환경 변수로 자동 컴팩션 시점 조절
    - 공식 발표(5배 확장)를 실사용자는 "작업이 안 끊긴다"로 번역해서 받아들이고 있음

*   **[00:05:10] ~ 패러다임 전환: 정보를 통째로 줘야 한다**

    - 기존 패턴의 역설: 컴팩션을 두려워해 AI에게 줄 정보를 스스로 줄이던 사용자. AI가 사람 눈치 보며 정보를 덜 요구하게 만든 구조
    - 핵심 통찰: 요약본만 주면 AI도 요약 수준의 판단밖에 못 함. 기획서 전문을 통째로 주면 전체 맥락을 이해하고 더 정확한 결과를 냄
    - 컨텍스트 확장 이후 가능해진 것: 기획서 전문·디자인 파일·이전 세션 노트·프로젝트 구조를 모두 제공 → 에이전트가 실력 발휘 가능
    - 트레이드오프: 컨텍스트 증가 → 매 요청 토큰 소모 가속 → 구독 한도 빠른 소진. 그러나 엉뚱한 결과로 재작업하는 것보다 충분한 정보로 한 번에 정확한 결과 받기가 더 효율적

*   **[00:06:30] ~ 정리: 실전 적용 요약**

    - 공식: 5배 확장, 가격 프리미엄 폐지, 미디어 600개, Opus 4.6은 100만에서도 78% 유일 유지
    - 현실: 100만을 다 쓰는 게 아니라 작업 끊김 방지 버퍼로 사용. 30만~40만 사이에서 정리하는 것이 실전 전략
    - 핵심 행동 변화: 정보를 아끼지 말 것. 기획서 전문·디자인 파일·이전 세션 노트·프로젝트 구조를 통째로 제공해야 AI가 실력을 냄. "이제 아낄 이유가 없어졌습니다"
