# Claude Code 스킬, 만든 사람들은 이렇게 쓰고 있었다

클로드 코드에 스킬 만들어 써 보신
분 계세요? 마크다운 파일 하나
만들어서 이렇게 해라 적어 놨는데
처음에 좀 되는 거 같더니 점점 말을
안 듣는 거예요. 분명히 다 써
놨는데 왜 또 이상하게 짜지? 왜
내가 시킨 대로 안 하지? 그래서
저도 궁금했어요. 스킬을 만든
사람들은 어떻게 쓰고 있을까?
엔스로픽에서 실제로 클로드 코드를
만든 팀이요. 그 사람들이 내부에서
수백개의 스킬을 운영하면서 발견한게
있대요. 그리고 그걸 공개했습니다.
오늘이 영상에서 그 핵심을 다 풀어
드릴게요. 이거 알고 나면 스킬
만드는 방식이 완전히 달라집니다.
먼저 제일 중요한 것부터
말씀드릴게요. 대부분의 사람들이
스킬을 마크다운 파일 하나로
생각해요. 스킬 MD 만들어서 거기에
이렇게 해라, 저렇게 해라 적어 놓고
끝. 근데 엔스로픽에서 실제로 잘
작동하는 스킬들은 그게 아니었어요.
스킬은 파일이 아니라 폴더예요. 이게
무슨 말이냐면요. 진짜 강력한 스킬은
이렇게 생겼어요. 스킬 MD라는 메인
지시문이 있고 그 옆에 레퍼런시스
폴더에 API 문서랑 코드 스니페이
들어 있고 스크립트 폴더에 검증용
스크립트가 있고 SF 폴더에 템플릿이
있고 쉽게 비유하면 이래요. 마크다운
파일 하나로 스킬을 만드는 건
레시피만 주는 거예요. 소금 놓고
끓여라. 근데 진짜 잘되는 스킬은
밀키트예요. 재료도 들어 있고 도구도
들어 있고 레시피도 들어 있고 열면
바로 만들 수 있는 왜 이게
되냐면요. 클로드는 폴더를 탐색할 수
있거든요. 필요한 파일을 알아서
읽어요. 지금 API 호출 부분
짜야겠다. 레퍼런시스 폴더에서 예제
읽고 결과물 형식 맞춰야겠다.
SS에서 템플릿 가져와서 쓰고이 파일
시스템 자체가 컨텍스트 엔지니어링의
도구가 되는 거예요. 그러니까 스킬
하나 만들 때 마크다운 하나 쓰는게
아니라 폴더 하나 설계한다고
생각하셔야 돼요. 좋아요. 스킬은
폴더다. 그럼 이제 뭘 만들어야
하는가? 엔스로픽에서 내부 스킬
수백개를 다 카탈로그화 해 봤대요.
그랬더니 아홉 가지 패턴으로
분류되더라는 거예요. 잠깐 여기서
재밌는 말이 하나 있어요. 좋은
스킬은 딱 하나의 유형에 깔끔하게
들어맞고 나쁜 스킬은 여러 유형에
걸쳐 있다. 하나씩 볼게요. 첫 번째
라이브러리 레퍼런스. 우리 팀에서
쓰는 내부 라이브러리러리가 있잖아요.
그 라이브러리의 사용법이랑 함정을
정리해 놓는 스킬이에요. 클로드가
모르는 우리만의 규칙. 두 번째 제품
검증. 플레이라이트 같은 도구랑
연결해서 코드가 제대로 동작하는지
자동으로 확인하는 스킬이에요.
엔스로픽에서는 이걸 아주 중요하게
보더라고요. 엔지니어 한 명이 일주일
투자해서 검증 스킬 하나를 완벽하게
만들고까지 했어요. 세 번째 데이터
조회 모니터링 도구나 분석 스택이랑
연결하는 스킬.네 번째 비즈니스
자동화 스탠드업 리포트 위클리 리캡
같은 반복 업무를 자동화하는
스킬이에요. 매일 기터부 활동 모아서
스탠드업 작성하는 거. 이거 스킬
하나로 됩니다. 다섯 번째 코드 스캡
홀딩. 새 프로젝트 만들 때 보일러
플레이트 자동 생성. 여섯 번째 코드
리뷰. 코드 스타일을 강제하거나 자동
리뷰해 주는 스킬. 일곱 번째
CICD PR 모니터링하고 자동
롤백하는 스킬. 여덟 번째 럼브.
장애 알림이 오면 자동으로 조사하고
보고서 만드는 스킬. 아홉 번째
인프라 운영. 쓸모 없는 리소스
정리하고 비용 분석하는 스킬. 이걸
왜 말씀드리냐면요.이 목록을
체크리스트로 쓰시면 돼요. 우리 팀에
아직 없는 유형이 뭐지? 이걸로
점검하는 거죠. 자, 이제 진짜
핵심이에요. 스킬을 어떻게 잘
쓰느냐. 앤스로픽이 강조한 첫 번째
원칙이 뭔지 아세요? 뻔한 말 하지
마라. 존트 스테이트 디오스.
클로드는 코딩을 이미 잘 알아요.
파이썬으로 API 호출하는 법. 그런
거 스킬에 쓸 필요 없거든요.
클로드가 이미 알아요. 스킬에 써야
하는 건 클로드가 절대 출론만으로 알
수 없는 것이에요. 우리 빌딩 립은이
함수 호출 전에 반드시 텐트 아이디를
먼저 설정해야 한다. 이런 거예요.
우리 조직만 아는 규칙, 우리 코드
베이스만의 함정, 재밌는 사례가 하나
있어요. 엔스로픽 내부에서 프론트
엔드 디자인 스킬이라는 걸
만들었대요. 클로드가 UI를 만들면
매번 인터폰트에 보라색 그라데이션을
쓰거든요. 클로드스러운 디자인이라고
부르더라고요. 그래서이 스킬에
인터포트 쓰지 마. 보라색 그라데이션
쓰지 마. 이런 걸 넣은 거예요.
클로드의 기본 성향을 깨는 정보.
그게 스킬에 담아야 할 내용이에요.
근데요. 여기서 더 중요한게 있어요.
엔스로픽이 이런 말을 했어요.
스킬에서 가장 높은 가치를 가진
콘텐츠는 가차스 섹션이다. 가차스가
뭐냐면요. 클로드가 반복적으로
실패하는 지점을 모아 놓은
목록이에요. 이게 왜 중요하냐면요.
스킬을 처음 만들 때는 완벽한
지시문을 쓰려고 해요. 이렇게 해라,
저렇게 해라,이 순서로 해라. 근데
아무리 잘 써도 클로드는 예상 못한
데서 실수하거든요. 그때 그 실수를
기록하는 거예요. 아, 클로드가이
함수 호출할 때 매번 순서를 바꾸네.
그러면 가차스에이 함수는 반드시 a
다음에 b로 호출해야 한다고 추가하는
거예요. 비유하면 이래요. 신입
사원이 들어왔을 때 매뉴얼을
주잖아요. 근데 진짜 도움되는 건
매뉴얼이 아니라 선배가 귀속 말로
알려주는 이건 절대 이렇게 하면 안
돼 목록이거든요. 그게 가차스예요.
그리고 엔스로픽이 한 말 중에 이게
인상적이었어요. 대부분의 스킬이
멸줄과 하나의 가차로 시작해서
사람들이 계속 추가하면서 좋아졌다.
그러니까 처음부터 완벽한 스킬을
만들려고 하지 마세요. 멸줄로
시작해서 클로드가 실수할 때마다
하나씩 추가하는 거예요. 스킬은 한
번 쓰고 끝나는 문서가 아니라 계속
잘하는 거예요. 다음 팁도 중요해요.
점진적 공개라는 건데요. 스킬 MD
하나에 모든 정보를 다 때려 놓으면
어떻게 될까요? 클로드의 컨텍스트가
터져요. 이전 영상에서 컨텍스트 관리
말씀드렸잖아요. 스킬도 똑같아요.
메인 파일에는 개요랑 파일 목록만
넣고 상세한 건 별도 파일로 빼는
거예요. 예를 들면 API 함수
시그니처 같은 건 레퍼런시스에 API
MD에 넣고 출력 템플릿은 SS에
템플릿 MD에 넣는 거예요. 클로드가
필요할 때만 알아서 읽어요. 한꺼번에
다 읽을 필요가 없는 거죠. 이게 왜
되냐면요. 스킬 MD에이 폴더에 이런
파일들이 있다라고만 써 놓으면
클로드가 알아서 판단해요. 지금
API 호출 코드를 짜야 하니까
API MD를 읽어 봐야겠다. 이런
식으로요. 밀키트 비유 기억나시죠?
밀키트 상자 권면에이 안에 고기 양념
채소가 있다라고 써 놨으면 요리사가
필요한 것만 꺼내 쓰는 거예요. 다
한꺼번에 쏟아붙지 않고. 자, 여기서
반전이 하나 있어요. 스킬을 아무리
잘 만들어도 클로드가 그 스킬을 안
쓰면 소용 없잖아요. 근데 많은
사람들이 여기서 실수해요. 스킬의
디스크립션이라는 필드가 있거든요.
대부분 여기에 배포 관련 스킬이라고
써요. 요약처럼요. 근데 이게
함정이에요. 디스크립션은 사람이 읽는
요약이 아니에요. 클로드가 읽는
트리거 조건이에요. 클로드 코드가
세션을 시작하면 설치된 모든 스킬의
디스크립션을 쭉 스캔해요. 그리고이
사용자의 요청에 맞는 스킬이 있나
판단하거든요. 그니까 배포 관련
스킬이라고 쓰면 클로드가 정확히
언제이 스킬을 써야 하는지 판단을 못
해요. 대신 이렇게 써야 돼요.
사용자가 서비스를 프로덕션에 배포하려
하거나 PR 머지 후 배포 상태를
확인하려 할 때 사용한다. 이렇게요.
차이가 느껴지시죠? 하나는이 스킬은
뭐다이고 다른 하나는 언제이 스킬을
켜라인 거예요. 클로드에게는 후자가
훨씬 명확하거든요. 스킬을 만들고 왜
클로드가 내 스킬을 안 쓰지 싶으셨던
분들 디스크립션부터 확인해 보세요.
거기가 문제일 확률이 높아요. 그리고
하나 더요. 스킬 안에 스크립트를
넣으세요. 클로드에게 헬퍼 함수
라이브러리러리를 주면 클로드가 보일러
플레이트를 매번 새로 짜는 대신
조합에 집중할 수 있어요. 데이터
분석 스킬이라면 이벤트 조회 함수,
코우트 비교 함수 같은 걸 미리
만들어서 스크립트 폴더에 넣어 두는
거죠. 마지막으로 진짜 강력한 기능
하나 알려 드릴게요. 스킬에 훅을
넣을 수 있어요. 온 디맨드 훅스라고
하는 건데요. 이게 뭐냐면 클로드가
도구를 쓰기 직전에 자동으로 검사하는
검문소를 설치하는 거예요. 근데이
검문소가 스킬을 호출할 때만 켜지고
세션 끝나면 자동으로 꺼져요. 예를
들어 볼게요. 슬래시케
careful풀이라는 스킬을 만든다고
해 봐요. 프로덕션 서버 작업할 때
쓰는 안전 모드예요.이 스킬을
호출하면 클로드가 배시 명령을 실행할
때마다 자동으로 검사가 돌아요. RN
- RF 차단, 드롭 테이블 차단,
깃푸시 포스 차단. 평소에는 이런
제약 없이 자유롭게 작업하다가 위험한
작업할 때만 슬래시 케어풀 치면 안전
모드가 켜지는 거예요. 작업 끝나면
자동으로 꺼지고요. 슬래시프리즈라는
것도 있어요. 디버깅할 때 쓰는 건데
특정 폴더만 수정할 수 있게 잠가
버리는 거예요. 로그 추가하려고 코드
열었더니 클로드가 옆에 있는 다른
파일도 고쳐 버리는 거 경험해
보셨죠? 그거 방지하는 거예요. 이게
그냥 편의 기능이 아니에요.
에이전트에게 모드를 부요하는 거예요.
평소에는 자유 모드 위험할 때는 안전
모드 디버깅할 때는 동결 모드 필요한
순간에만 가드레이를 올렸다 내렸다 할
수 있는 거죠. 스킬을 혼자만 쓰면
아깝잖아요. 팀에 공유하는 방법도
있어요. 작은 팀이면 레퍼의 다클로드
스킬즈 폴더에 그냥 넣으면 돼요.
팀원 모드가 같은 스킬을 쓸 수
있어요. 근데 팀이 커지면 문제가
생겨요. 스킬이 많아지면 클로드의
컨텍스트를 잡아먹거든요. 그래서
엔스로픽은 플러그인 마켓플레이스
방식을 쓰고 있어요. 필요한 사람만
골라서 설치하는 거죠. 엔스로픽
내부에서는 이렇게 운영한대요. 누구나
샌드박스 폴더에 스킬을 올릴 수 있고
슬랙에서 홍보하고 사람들이 실제로
많이 쓰면 그때 공식 마켓에 올리는
거예요. 중앙에서 관리하는게 아니라
자연스럽게 좋은 스킬이 올라오는
구조. 정리할게요. 오늘 핵심은
이거예요. 스킬은 마크다운 파일이
아니라 폴더예요. 클로드가 이미 아는
걸 반복하지 말고 클로드가 실패하는
지점을 기록하세요. 그게 가차 쓰고
그게 스킬에서 가장 가치 있는
부분이에요. 디스크립션은 요약이
아니라 트리거 조건이고 파일 시스템은
점진적 공개의 도구이고 온 디맨드
훅수로 상황별 모드를 만들 수
있어요. 그리고 가장 중요한 거예요.
