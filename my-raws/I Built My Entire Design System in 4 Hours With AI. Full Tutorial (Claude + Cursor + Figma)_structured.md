## 📝 1. 영상 전체 요약

> Figma MCP와 Claude를 연동하여 단 4시간(한 오후)에 디자인 시스템 전체를 TypeScript 코드로 구축하는 실전 튜토리얼로, 스타일 토큰 생성 → 컴포넌트 라이브러리 구축 → 실제 피처 개발까지의 전체 워크플로우와 함께 채팅 기록을 프로젝트 컨텍스트로 저장하는 팀 협업 팁을 제공한다.

## 📖 2. 영상 주요 주제 (추상화된 목차)

*   **[도입 — 디자인-코드 핸드오프 문제와 해결 방향]**

    - **세부 주제:** 현실 문제 제기: 62%의 개발자가 Figma↔코드 간 핸드오프 불일치로 디자인을 처음부터 재구현하며 시간을 낭비. 팀의 피처 배포 속도 차이(2주 vs 2시간)의 원인.
    - **세부 주제:** 해결책 — 코드 기반 디자인 시스템: Figma MCP + Claude를 활용해 Figma 컴포넌트 라이브러리를 TypeScript 코드로 직접 추출·코드화하는 접근법. 과거에는 수일~수주가 걸렸으나 이제 한 오후로 단축.

*   **[1단계 — 스타일 가이드(Design Tokens) 생성]**

    - **세부 주제:** Figma MCP 연동: Claude가 MCP 연결을 통해 Figma 파일에서 색상·타이포그래피·스페이싱·보더 등 모든 디자인 값을 직접 추출.
    - **세부 주제:** `style-tokens.ts` 생성: 모든 디자인 토큰을 TypeScript 파일 하나에 정의하고 스타일 가이드 페이지 자동 생성. 이 파일이 이후 모든 컴포넌트의 단일 진실 원천(Single Source of Truth)이 됨.
    - **세부 주제:** 새 Claude 창 전략: 프로젝트의 각 피처·파트마다 새 Claude 대화창을 열어 컨텍스트를 격리하는 것이 핵심 팁.

*   **[2단계 — 컴포넌트 라이브러리 구축]**

    - **세부 주제:** 컴포넌트 명세 구조: 인터랙션·디자인 스펙·동작 방식이 Figma 파일에서 추출되어 개발자·디자이너 모두가 참조하는 명세서로 구성. 사용 예시(Usage Example)도 포함.
    - **세부 주제:** 6단계 구축 워크플로우 프롬프트: ① 초기화·설정·분석(Figma 파일 읽기) → ② 컴포넌트 데이터 추출(호버·인터랙션 포함) → ③ 시각 스펙 준수 → ④ 동작 스펙 적용 → ⑤ TypeScript로 컴포넌트 구현(전체 variants 포함) → ⑥ 문서(.txt) 생성.
    - **세부 주제:** 자동 Task List 실행: Claude Code가 워크플로우 단계를 태스크 리스트로 변환하고 각 단계를 완료 체크하며 순차 실행. KPI 카드 컴포넌트가 Figma와 픽셀 퍼펙트로 일치하는 결과 생성.
    - **세부 주제:** 컴포넌트 문서화: 각 컴포넌트마다 사용된 토큰·구현 방식이 담긴 .txt 문서 자동 생성. 변경 시 파일 하나 업데이트로 전체 적용처에 반영.

*   **[3단계 — 실제 피처(화면) 개발]**

    - **세부 주제:** 컴포넌트 조합으로 화면 구성: 구축된 컴포넌트들을 조합하여 실제 제품 화면을 빌드. 동일한 6단계 워크플로우 프롬프트 재사용.
    - **세부 주제:** 반복 수정 워크플로우: 초안에서 스페이싱 이슈 발견 → Claude에 수정 지시 → 디자인 토큰 값(예: 16pt)에 맞춰 즉시 수정 완료. Figma 디자인과 완벽히 일치.

*   **[프로젝트 컨텍스트 관리 및 권장 시작 순서]**

    - **세부 주제:** 채팅 기록 저장: 각 대화 종료 전 "이 채팅 기록을 project-context.md에 저장해줘" 요청 → 세션 날짜·작업 내용 자동 기록. 여러 채팅창 간 프로젝트 흐름 연속성 유지.
    - **세부 주제:** 권장 시작 순서: ① 스타일 가이드 먼저 구축 → ② 컴포넌트 하나씩 구축 → ③ 컴포넌트 기반 피처 개발 → ④ notes.md로 메모 관리.

*(참고: 이 항목은 영상의 논리적 구조를 추상화하여 그룹화한 것이며, 시간 정보는 포함되지 않습니다.)*

## ⏳ 3. 주요 시간대별 상세 요약

*   **[00:00:00] ~ 도입 — 왜 코드 기반 디자인 시스템인가**

    - 팀의 배포 속도 비교: 일반 팀 2주 vs 이 팀 2시간. 차이는 코드 기반 디자인 시스템 구축 여부.
    - 62%의 개발자가 Figma↔코드 핸드오프 불일치로 디자인을 처음부터 재구현. 역사적으로 복잡·시간 소요가 커서 도입이 어려웠지만 AI로 한 오후에 해결 가능해짐.
    - Figma 컴포넌트 라이브러리(파운데이션·색상·타이포그래피·아이콘)를 Claude가 읽어 코드로 변환하는 개요 소개.

*   **[00:01:30] ~ 1단계 — 스타일 가이드 생성**

    - 새 Claude 대화창 오픈 (피처/파트마다 새 창을 여는 것이 핵심).
    - 프롬프트: "스타일 가이드 생성. 파일명 style-tokens.ts. 색상 변수·타이포그래피·스페이싱·보더 포함. 스타일 가이드 페이지 생성. Figma MCP에서 값 추출."
    - 결과: 색상 팔레트·아이콘·사용 권장사항 등이 Figma MCP에서 자동 추출되어 TypeScript로 코드화. 이후 모든 컴포넌트의 단일 진실 원천 확보.

*   **[00:03:00] ~ 2단계 — 컴포넌트 라이브러리 구축 (KPI 카드 예시)**

    - 컴포넌트 명세 구조 설명: 인터랙션·디자인·동작 방식이 Figma에서 추출되어 개발자·디자이너 공통 참조 문서로 활용. 사용 예시 포함.
    - 6단계 워크플로우 프롬프트 실행:
      1. 초기화·설정·분석 (Figma 파일 읽기)
      2. 컴포넌트 데이터 추출 (호버·인터랙션 포함, 단순 시각 복사가 아닌 동작 방식까지 추출)
      3. 시각 스펙 준수
      4. 동작 스펙 적용
      5. TypeScript 컴포넌트 구현 (전체 variants, 프리뷰, 디자인 토큰 적용)
      6. 문서(.txt) 생성 및 컴포넌트 페이지 추가 탭에 배치
    - Claude Code가 태스크 리스트를 자동 생성하고 각 단계를 체크하며 순차 실행.
    - 결과: Metric Card 컴포넌트가 Figma 디자인과 완벽 일치 + 사용 토큰·구현 방식이 담긴 문서 자동 생성.

*   **[00:06:00] ~ 3단계 — 실제 화면(피처) 개발**

    - 구축된 KPI 카드·기타 컴포넌트들을 조합해 실제 제품 화면 빌드.
    - 새 Claude 대화창에서 동일한 워크플로우 프롬프트 재사용: Figma 화면 스펙 분석 → 컴포넌트 조합 → 레이아웃 구성 → 디자인 토큰 적용.
    - 초안에서 스페이싱 이슈 발견 → "16pt로 수정해줘" 지시 → 즉시 수정 완료. Figma 디자인과 일치 확인.
    - 이후 추가 컴포넌트를 점진적으로 빌드온하여 완성도 향상.

*   **[00:08:30] ~ 프로젝트 컨텍스트 저장 팁**

    - 각 대화 종료 전 "이 채팅 기록을 project-context.md에 저장해줘" 요청.
    - Claude가 세션 번호·날짜·해당 세션 작업 내용을 자동으로 기록.
    - 여러 대화창 간 프로젝트 흐름의 연속성 유지 및 팀 협업 시 맥락 공유에 활용.

*   **[00:09:00] ~ 마무리 — 권장 시작 순서**

    - ① 스타일 가이드(style-tokens.ts) 먼저 구축
    - ② 컴포넌트 하나부터 시작
    - ③ 구축된 컴포넌트로 실제 피처 개발
    - ④ notes.md로 진행 메모 관리
    - 목표: AI를 활용한 빠른 제품팀 구축. 디자인 시스템 코드화로 Figma↔코드 핸드오프 문제 근본 해결.

*(이후 영상 끝까지 중요한 흐름이 바뀔 때마다 시간대별 요약 추가)*
