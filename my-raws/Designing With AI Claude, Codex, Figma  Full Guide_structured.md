## 📝 1. 영상 전체 요약

> UI 디자이너 관점에서 Google Stitch(빠른 초기 탐색)→Claude/Claude Design(고품질 첫 번째 초안)→Codex(효율적 반복)→Figma(수정·정리)→Claude Code(개발자 배포)로 이어지는 AI 디자인 풀 워크플로우를 설명하고, Figma MCP·스킬 설치 방법과 "디자인 시스템을 AI에게 가르치는" 3단계 커스텀 스킬 제작 방법을 상세히 안내한다.

## 📖 2. 영상 주요 주제 (추상화된 목차)

*   **[AI 디자인의 현실: 단일 도구 환상 깨기]**

    - **세부 주제:** AI는 도구가 아니라 워크플로우: Figma 하나만 쓰던 시대와 달리, AI 시대에는 여러 도구의 협업 방식을 이해하는 것이 핵심. 도구 하나만 알면 커리어에서 뒤처질 위험.
    - **세부 주제:** 디자이너가 원하는 꿈의 AI(디자인 시스템 완벽 인식→원샷 프롬프트 빌드→Figma 수준 세밀 조정→원클릭 핸드오프)와 현실 간의 격차: 아직 존재하지 않음. 대신 훈련·반복·문서화·멀티툴 협업이 필요.
    - **세부 주제:** Figma의 현 위상: 여전히 필수이나 AI 기능이 크게 뒤처짐. Figma Make의 디자인 시스템 동기화가 잘 작동하지 않으며 AI 결과물이 제네릭. Claude/Codex/Claude Design/Google Stitch가 더 나은 결과 제공.

*   **[핵심 도구 비교: Claude vs. Codex vs. Claude Design vs. Google Stitch]**

    - **세부 주제:** Claude vs. Codex: Claude는 코드 품질이 더 높고 Figma 속성(Auto Layout·반응형) 적용이 더 정확함. Codex는 동일 작업에 토큰을 3~4배 적게 소모하고 빠름. 초안 생성은 Claude, 반복 작업은 Codex가 효율적.
    - **세부 주제:** Claude Design: 고품질 UI를 빠르게 생성하나 느리고(단순 대시보드 생성에 6~8분) 토큰 소모가 크며 디자인 시스템 임포트가 불완전. Figma처럼 요소를 직접 이동·수정하기 어려움. 충분히 알아보고 사용해야 함.
    - **세부 주제:** Google Stitch: 무료에 가깝고 빠름(15초 내 결과). 모바일 디자인에 강하고 데스크톱은 약함. 디자인 시스템 훈련 불가. 폴리시된 결과물 아니나 초기 탐색·내부 이해관계자 소통용 미드파이 와이어프레임으로 최적.

*   **[셋업: Figma MCP와 Figma 스킬 설치]**

    - **세부 주제:** Figma MCP vs. Figma Skills 차이: MCP는 AI가 Figma 파일을 읽고 접근할 수 있게 해주는 연결 장치. Skills는 AI에게 Auto Layout·변수·컴포넌트 사용법을 가르치는 교육 파일. 둘 다 필요.
    - **세부 주제:** Claude에서 설치: Figma 커뮤니티 스킬 사이트에서 "Figma U Skill" GitHub ZIP 다운로드 → Claude 커스터마이즈 페이지에서 플러그인 업로드. Connectors 탭에서 Figma MCP를 별도로 Connect해야 실제 파일 접근 가능. "apply design system" 스킬과 "audit design system" 스킬(가장 유용) 추가 설치 권장.
    - **세부 주제:** Codex에서 설치: 플러그인 탭에서 Figma 플러그인 설치(Claude ZIP 불필요). 개인 플랜에서 가용 여부가 유동적이며 이 경우 Skills 탭에서 개별 스킬 검색·설치로 대체. 두 툴에 동일 스킬이 설치되어야 워크플로우 동기화 가능.

*   **[단계별 워크플로우: 어떤 툴을 언제 쓸 것인가]**

    - **세부 주제:** Google Stitch → Claude Design/Code 순서의 이유: Stitch로 초기 개념(어떤 데이터를, 어떤 위젯으로, 어떤 배치로)에 대한 내부 합의 → Claude에서 충분히 알아본 뒤 최소한의 반복으로 고품질 결과 생성. "Claude Design 1 프롬프트 = 내 주간 사용량의 8%" 사례처럼 토큰 낭비 방지.
    - **세부 주제:** Claude → Figma → Codex → Figma → Claude 순환 워크플로우: Claude에서 고품질 초안 → Figma로 푸시하여 레이아웃·스타일 수동 조정 → Codex에서 저렴한 반복(같은 변경 기준 Claude 12분 38K 토큰 vs. Codex 4분 17K 토큰) → Figma에서 최종 정리 → Claude Code로 개발자 배포. 작은 변경 1~2개는 Claude에서 직접 처리가 효율적.
    - **세부 주제:** Codex의 한계: 바닐라 프롬프트로 생성되는 UI 품질이 Claude보다 현저히 낮음. 단독으로 디자인 생성보다는 Claude 또는 Figma에서 가져온 디자인의 반복에 특화.

*   **[디자인 시스템과 AI: 무엇을 AI에게 맡기고 무엇은 직접 해야 하나]**

    - **세부 주제:** Claude Design의 디자인 시스템 임포트 한계: 실제로 업로드해도 컴포넌트 변형·타입 스케일·변수를 완전히 인식하지 못함. 버튼 variant 누락, 타이포그래피 단계 누락 등 여전히 불완전. 상사가 "그냥 임포트하면 되지 않나"라고 할 때 직접 데모 시연 권장.
    - **세부 주제:** "AI에게 시키면 안 되는 것": 변수 라이브러리·단순 컴포넌트(버튼·폼 필드·체크박스 등)를 AI로 생성하면 시간·토큰 낭비. AI가 준 출력물을 역공학하는 데 더 오래 걸림. 대신 $50~$150짜리 Figma 커뮤니티 유료 템플릿 또는 직접 학습이 효율적. AI는 복잡한 모달·대시보드·테이블 위젯 등 큰 레이아웃에 집중.
    - **세부 주제:** 변수를 직접 만들어야 하는 이유: 직접 만들어야 각 변수의 사용 시점과 목적을 명확히 알고 AI 스킬에 정확히 기술 가능. AI가 만든 변수 라이브러리는 disabled 상태 누락 등 결함이 있으며, "AI가 뭘 누락했는지 모르면 성공할 수 없음".

*   **[AI에게 디자인 시스템 가르치기: 커스텀 스킬 3단계]**

    - **세부 주제:** 1단계 — 변수 스킬 생성: Figma에 변수 이름·값(라이트/다크 모드)·사용 시점 표 준비 → 링크 붙여넣어 Claude에 "이 변수들을 숙지 후 Claude 스킬 생성, surface·border·text·icon 변수만 포함" 요청. 결과: 변수 그룹별 MD 파일과 skill.md 생성.
    - **세부 주제:** 2단계 — 타입 스타일 스킬 생성: 텍스트 스타일 + 적용된 변수(데스크톱·모바일) 확인 → "모든 텍스트 스타일과 변수 숙지 후 어떤 스타일이 사용 가능한지 알리는 Claude 스킬 생성" 요청. 이 스킬이 없으면 AI가 디자인 시스템에 없는 임의 폰트 크기를 사용.
    - **세부 주제:** 3단계 — 컴포넌트 스킬 생성: Figma 컴포넌트를 Form Elements·Navigation·Data Display 3그룹으로 구조화 → "그룹 순서대로 완전히 숙지 후 다음으로 이동, 완료 후 컴포넌트 사용 시점 스킬 생성" 요청. 그룹화로 AI가 atom 컴포넌트를 놓치는 문제 방지.
    - **세부 주제:** Claude→Codex 스킬 동기화: Claude에서 "모든 스킬을 개별 ZIP 폴더로 패키징" 요청 → 다운로드 → Codex 채팅에 ZIP 업로드로 동일 스킬 설치. 이후 어느 툴에서 작업해도 동일한 디자인 시스템 기준 유지.

*   **[비주얼 레퍼런스 활용: 더 나은 AI 출력물 얻기]**

    - **세부 주제:** Mobin 활용법: 실제 앱 화면·플로우 레퍼런스 라이브러리. 좋아하는 화면 스크린샷 → Claude에 "이 예시를 참고하여 우리 디자인 시스템으로 빌드" 제공. 반드시 2~3개 이상 예시 제공으로 디자인이 특정 앱의 1:1 복사본이 되지 않도록. Figma 플러그인으로 스크린샷 직접 Figma 업로드 가능.
    - **세부 주제:** ChatGPT 5.5 이미지 생성 활용: 기존 디자인 스크린샷을 ChatGPT 5.5에 붙여넣어 "다른 버전 생성" 요청 → 원본과 다른 변형 획득 → Claude에 다시 넣어 디자인 시스템 반영. Codex와 달리 채팅 플랜에 포함, 빠르고 무료에 가까움.
    - **세부 주제:** Figma 푸시 전 주의사항: Claude에서 Figma로 푸시할 때 "디자인 시스템 참고 + 텍스트 스타일·변수·컴포넌트 스킬 명시 + 아직 Figma로 푸시하지 말 것" 프롬프트 권장. Figma로 푸시 전 최대한 로컬에서 정제 후 Figma에서 최종 정리 → Codex 또는 Claude Code로 이동.

*(참고: 이 항목은 영상의 논리적 구조를 추상화하여 그룹화한 것이며, 시간 정보는 포함되지 않습니다.)*

## ⏳ 3. 주요 시간대별 상세 요약

*   **[00:00:00] ~ 도입: AI는 도구가 아닌 워크플로우**

    - Figma 단일 도구 시대의 끝. 이제 Google Stitch·Claude·Codex·Claude Design·Figma를 어떻게 조합하느냐가 핵심. 하나만 알면 커리어에서 뒤처짐.
    - 디자이너의 "꿈의 AI": 디자인 시스템 완벽 인식 + 원샷 빌드 + Figma 수준 조정 + 원클릭 핸드오프 → 현재 존재하지 않음. 훈련·반복·멀티툴 협업이 현실.

*   **[00:04:00] ~ 툴 선택: Claude vs. Codex 핵심 차이점**

    - Claude: 코드 품질 우수, Figma 속성(Auto Layout·Fill·Hug) 적용 더 정확, 개발자 선호. Codex: 동일 작업 대비 토큰 3~4배 절약, 속도 빠름.
    - Claude 유료 플랜에서도 복잡한 디자인 반복 시 토큰 소진 빠름. Uber가 AI 개발 예산을 3~4개월 만에 소진한 사례 언급 → 토큰 전략 중요.

*   **[00:06:00] ~ 셋업: Figma MCP와 스킬 설치**

    - Claude 설치: Figma 커뮤니티 스킬 사이트에서 Figma U Skill ZIP 다운로드 → Claude 커스터마이즈에서 플러그인 업로드. Connectors 탭에서 Figma 연결 별도 필요. "audit design system" 스킬이 특히 유용(디자인 시스템 적용 오류 자동 감지·수정).
    - Codex 설치: 플러그인 탭에서 Figma 플러그인(개인 플랜 가용성 유동적) 또는 Skills 탭에서 개별 스킬 검색 설치. Claude와 Codex에 동일 스킬 환경 구축이 목표.

*   **[00:10:00] ~ Google Stitch: 초기 탐색의 정석**

    - 같은 프롬프트(금융 어드바이저 앱) 기준 모바일: 30초 내 결과, 깔끔한 구조 제시. 데스크톱: 훨씬 열악한 결과. Stitch = 모바일 강점.
    - 변형 생성(Explore/Reimagine) 기능으로 다양한 레이아웃·메트릭 배치 옵션 탐색. 이해관계자와 "어떤 데이터를 어떻게 보여줄까" 초기 합의에 최적. 프로덕션 레벨 아니므로 외부 공개 금지.
    - 언제 쓰나: Stitch로 방향 합의 후 Claude Design/Code로 이동. Stitch 없이 바로 Claude 사용하면 불필요한 반복으로 토큰 낭비.

*   **[00:15:00] ~ Claude Design: 고품질 단 사용량 주의**

    - 같은 금융 앱 프롬프트로 Claude Design은 질문 후 6~8분 후 시니어 수준의 대시보드 생성. Stitch 결과와 품질 차이 명확. 단, 하나의 대시보드에 사용량의 8% 소진.
    - 디자인 시스템 임포트 테스트: 버튼 변형 누락, 타입 스케일 불완전(Display·H3·H5·H6·Body Medium 등 미인식). 2~3주 전보다 나아졌으나 아직 완전하지 않음. "그냥 임포트하면 되지 않나"라는 상사에게는 직접 데모 시연 권장.
    - Figma 수준의 직접 이동/수정 불가. 수정은 댓글/편집 기능 또는 AI 프롬프트로만 가능. 캔버스 경험이 Figma보다 정적.

*   **[00:22:00] ~ Claude Code vs. Codex: 실험 비교**

    - Claude: 초안 디자인 생성 후 Figma로 푸시. Codex: Claude가 만든 디자인을 Figma 링크로 가져와 재현. 동일 4가지 변경(라이트 모드 전환, 검색바 추가, 풀 너비, 카드 위치 교환) 기준 Claude 12분/38K 토큰, Codex 4분/17K 토큰.
    - 결론: 큰 복잡한 변경이 많을 때 Codex가 효율적. 작은 변경 1~2개는 Claude에서 직접 처리가 오히려 나음(Figma 왕복 오버헤드 때문).

*   **[00:28:00] ~ 디자인 시스템: AI로 해선 안 되는 것**

    - 변수 라이브러리를 AI에게 생성시키면: disabled 변수 누락, 브랜드 맞춤 불가, 결과물을 역공학하는 시간이 직접 만드는 시간보다 더 걸림. 무료/유료 Figma 템플릿($50~$150) 또는 직접 학습이 훨씬 효율적.
    - 버튼 컴포넌트 AI 생성 테스트: 6분 + 5,400 토큰 → success/warning 변형 누락, 접근성 색상 대비 미검증. "버튼은 디자인 시스템에서 가장 쉬운 컴포넌트인데 이 결과물이면, 복잡한 컴포넌트는 더 심각" → AI는 복잡한 레이아웃·모달·대시보드 위젯에 집중해야.

*   **[00:38:00] ~ AI에게 디자인 시스템 가르치기: 커스텀 스킬 3단계**

    - 1단계 변수 스킬: 변수 이름·값·라이트/다크 모드·사용 시점 표 Figma 링크 → "숙지 후 surface·border·text·icon 변수 Claude 스킬 생성, 타입 스타일 제외" 프롬프트. 결과로 그룹별 MD 파일 + skill.md 생성.
    - 2단계 타입 스타일 스킬: 텍스트 스타일 + 변수(데스크톱/모바일) Figma 링크 → "완전히 숙지 후 어떤 스타일이 사용 가능한지 알리는 스킬 생성" 프롬프트. 이 스킬 없으면 AI가 임의 폰트 크기(예: 15px) 사용 → 디자인 시스템 적용 불가.
    - 3단계 컴포넌트 스킬: Form Elements·Navigation·Data Display 3그룹으로 구조화 → "이전 그룹 완전 숙지 후 다음으로 이동, 컴포넌트·속성·변형·사용 시점 Claude 스킬 생성, 그룹별 개별 MD 파일" 프롬프트. 그룹화로 atom 컴포넌트 누락 방지.
