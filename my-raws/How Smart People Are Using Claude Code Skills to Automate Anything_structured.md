## 📝 1. 영상 전체 요약

> 대부분의 사람들이 스킬을 개별적으로 사용하는 실수를 지적하며, 공유 브랜드 컨텍스트(Layer 1)·학습 루프(Layer 2)·자가 유지보수(Heartbeat)·스킬 체이닝의 4개 레이어로 구성된 에이전틱 OS 아키텍처를 공개하고, 피드백이 쌓일수록 스스로 진화하는 완전한 비즈니스 운영체제 구축 방법을 제시한다.

## 📖 2. 영상 주요 주제 (추상화된 목차)

*   **[스킬 구조의 올바른 이해: 범용 스킬의 한계]**

    - **세부 주제:** 스킬의 기본 구조: `skill.md`(단계별 지침) + 레퍼런스 파일(브랜드 보이스·ICP·샘플 아웃풋 등 딥 노리지). 레퍼런스 파일이 프로세스를 "나만의 것"으로 만드는 핵심
    - **세부 주제:** 범용 스킬의 한계: GitHub·마켓플레이스에서 다운로드한 스킬은 의도적으로 범용으로 설계됨. 비즈니스 고유 지식을 채워 넣지 않으면 제네릭 결과물만 출력 — 플러그앤플레이가 아님

*   **[Layer 1 — 공유 브랜드 컨텍스트: 스냅샷]**

    - **세부 주제:** "start here" 명령 하나로 온보딩: 시스템이 비즈니스·타겟·톤·차별화 요소를 질문 → 세 가지 파운데이션 스킬(브랜드 보이스 추출·포지셔닝·ICP)이 답변을 처리해 구조화된 마크다운 파일로 저장. 일회성 설정으로 완료
    - **세부 주제:** 브랜드 컨텍스트 폴더 구성: 보이스 프로파일·포지셔닝·ICP·샘플 아웃풋·에셋(링크·핸들·비주얼 레퍼런스). 모든 스킬이 동일한 폴더를 참조 → 카피라이팅·콘텐츠 리퍼포징·UGC 스크립트·트렌드 리서치 모두 동일한 진실의 원천 사용

*   **[Layer 2 — 컨텍스트 폴더: 진화하는 관계]**

    - **세부 주제:** 컨텍스트 폴더 구성(OpenClaw 방식에서 영감): `soul.md`(에이전트 아이덴티티·행동 방식·우선순위), `user.md`(사용자 선호도·작업 스타일 — "간결한 불렛 포인트 선호"가 영구 저장됨), `memory.md`(장기 비즈니스 지식), 단기 일일 메모리 파일
    - **세부 주제:** 단기 메모리: 어제 작업한 것·지난주 생산물·현재 진행 중인 것을 로그로 유지. 새 세션 시작 시 연속성 확보 — "새 세션을 시작하는 게 아니라 이어서 작업"
    - **세부 주제:** learnings.md — 가장 강력한 요소: 주요 산출물 후 피드백 수집("리서치가 유용했나?", "뉴스레터가 너무 길었나?") → 해당 스킬 섹션에 기록 → 세션 종료 시 `skill.md` 파일 자동 업데이트. 다음 실행 시 스킬이 learnings를 먼저 읽음 → 같은 피드백 반복 불필요

*   **[자가 유지보수: Heartbeat와 Wrap-Up]**

    - **세부 주제:** Heartbeat (세션 시작 시 자동 실행): 스킬 폴더를 스캔해 디스크 상태와 `CLAUDE.md`·README에 문서화된 내용을 비교. 새 스킬 추가 시 자동 등록·컨텍스트 매트릭스 업데이트·learnings.md 섹션 추가 — 수동 관리 불필요. MCP 서버 등 새로 추가된 모든 것에 적용
    - **세부 주제:** 스킬 생성 시 중복 방지: 새 스킬 만들기 전에 기존 스킬의 프론트매터를 모두 읽어 오버랩·의존성 확인. 새 스킬이 기존 생태계에 깔끔하게 통합되도록 보장
    - **세부 주제:** Wrap-Up 스킬 (세션 종료 시 실행): "close session" 명령 하나로 트리거. 생산 산출물 검토·피드백 수집·스킬 업데이트·learnings 갱신·전체 작업 커밋. Heartbeat 재실행으로 동기화 완료 → "레지스트리 파일을 다시는 직접 업데이트하지 않아도 되는 지점"

*   **[스킬 체이닝: 컬렉션에서 운영체제로]**

    - **세부 주제:** 스킬 카테고리 구조: Foundation(브랜드 보이스·ICP·포지셔닝) → Execution(카피라이팅·UGC 스크립트·UGC 영상/이미지) → Strategy(트렌드 리서치) → Ops(크론 잡). 카테고리 간 상호 연결
    - **세부 주제:** 체이닝 예시: 트렌드 리서치 스킬(Reddit·X 핫토픽 수집 → research-brief 저장) → 콘텐츠 리퍼포징 시스템(최신 YouTube 영상 + 트렌드 리서치 → 뉴스레터 생성, Humanizer로 AI 느낌 제거, YouTube 툴로 자동 전사). 모든 단계에서 브랜드 컨텍스트 참조 + learnings로 보정
    - **세부 주제:** 스킬 설치 시 의존성 자동 파악: 스킬 설치 시 필요한 서브스킬도 자동 설치. "20개 개별 도구를 관리하는 게 아니라 하나의 시스템을 운영하는 것" — 마케팅·전략·운영·크리에이티브가 동일한 브레인을 공유

*(참고: 이 항목은 영상의 논리적 구조를 추상화하여 그룹화한 것이며, 시간 정보는 포함되지 않습니다.)*

## ⏳ 3. 주요 시간대별 상세 요약

*   **[00:00:00] ~ 도입: 스킬을 잘못 사용하는 대부분의 방식]**

    - 흔한 실수: 카피 스킬, 리서치 스킬, SNS 스킬을 각각 따로 사용 → 여전히 대부분의 일을 직접 함
    - 올바른 방식: 스킬들을 연결해 시스템으로 구성. "하나가 브랜드 컨텍스트를 구축하고, 다른 하나가 트렌드를 리서치하고, 또 다른 하나가 그 지식을 바탕으로 콘텐츠를 작성하고, 마지막 하나가 자동으로 실행"
    - 결론: 이 단계에 도달하면 Claude가 단순히 작업을 돕는 게 아니라 비즈니스의 전체 부문을 운영

*   **[00:01:30] ~ 스킬의 올바른 구조와 범용 스킬의 한계]**

    - 스킬 구조: `skill.md`(지침) + 레퍼런스 파일(브랜드 보이스·ICP·샘플). 레퍼런스 파일이 "프로세스를 나만의 것으로 만드는 요소"
    - 카피라이팅 스킬 예시: `skill.md`가 브랜드 컨텍스트 폴더(voice.md, icp.md, samples)를 참조 → 스킬 실행 시 어떻게 들려야 하는지, 누구를 위해 쓰는지 이미 알고 있음
    - 범용 스킬의 한계: GitHub·마켓플레이스 스킬은 의도적으로 범용 설계 → 비즈니스 지식 없이 사용하면 제네릭 결과물만 출력

*   **[00:03:00] ~ Layer 1: 브랜드 컨텍스트 구축 — 3가지 파운데이션 스킬]**

    - "start here" 명령: 브랜드·오디언스·톤·차별화에 대한 질문 시리즈 → 세 파운데이션 스킬(브랜드 보이스 추출·포지셔닝·ICP)이 응답을 처리해 구조화된 파일 생성
    - 브랜드 컨텍스트 폴더 결과물: 보이스 프로파일·포지셔닝·ICP·샘플·에셋(링크·핸들·비주얼 레퍼런스). 모든 파일이 편집 가능한 마크다운
    - 효과: 모든 스킬(카피라이팅·콘텐츠·UGC·트렌드 리서치)이 동일한 폴더에서 읽음 → 공유 진실의 원천

*   **[00:05:00] ~ Layer 2: 컨텍스트 폴더 — 시스템이 살아있게 만드는 것]**

    - 브랜드 컨텍스트가 "스냅샷"이라면, 컨텍스트 폴더는 "진화하는 관계" (OpenClaw 메모리 관리 방식에서 영감)
    - 구성 파일: `soul.md`(에이전트 아이덴티티), `user.md`(사용자 선호도·작업 스타일), `memory.md`(장기 지식), 단기 일일 메모리(어제 작업·지난주 생산물·진행 중인 것)
    - 단기 메모리의 효과: 새 세션 시작 시 이전 세션에서 이어서 작업 가능. 맥락이 끊기지 않음
    - learnings.md: 주요 산출물 후 피드백 수집 → 스킬별 섹션에 기록 → 세션 종료 시 `skill.md` 자동 업데이트 → "같은 피드백을 두 번 말할 필요가 없어지는 지점"

*   **[00:07:30] ~ 자가 유지보수: Heartbeat와 Wrap-Up]**

    - Heartbeat (세션 시작 자동 실행): 스킬 폴더 스캔 → 문서와 실제 디스크 상태 비교 → 새 스킬·MCP 서버 자동 등록, 컨텍스트 매트릭스 업데이트, learnings.md 섹션 추가
    - 새 스킬 생성 시 중복 방지: 기존 스킬 프론트매터 전체 읽어 오버랩·의존성 체크 → 새 스킬이 기존 생태계에 깔끔하게 통합
    - Wrap-Up 스킬 (세션 종료): "close session" 명령 → 산출물 검토·피드백 수집·스킬 업데이트·learnings 갱신·작업 커밋·Heartbeat 재실행. "레지스트리 파일·문서 싱크를 다시는 수동으로 하지 않아도 됨"

*   **[00:09:30] ~ 스킬 체이닝: 에이전틱 OS의 완성]**

    - 스킬 카테고리: Foundation → Execution → Strategy → Ops(크론 잡). 카테고리 간 상호 연결
    - 체이닝 예시 — 콘텐츠 파이프라인: 트렌드 리서치 스킬(Reddit·X 핫토픽 → research-brief.md) → 콘텐츠 리퍼포징(최신 YouTube 영상 전사 + 트렌드 리서치 → 뉴스레터 초안 → Humanizer로 AI 느낌 제거). 모든 단계에서 브랜드 컨텍스트 + learnings 참조
    - 의존성 자동 설치: 스킬 설치 시 필요한 서브스킬 자동 설치
    - 결론: "20개 개별 도구 관리" → "하나의 시스템 운영". 마케팅·전략·운영·크리에이티브가 동일한 브레인과 목표를 공유

*   **[00:12:00] ~ 시작하는 두 가지 방법]**

    - 방법 1 — 직접 구축: 브랜드 컨텍스트 설정 → 파운데이션 스킬(보이스·ICP) → 실행 스킬(트렌드 리서치·카피라이팅) → learnings 루프 추가. 학습량은 크지만 시간 소요
    - 방법 2 — 다운로드: Agentic OS 전체(모든 스킬·레퍼런스 파일·브랜드 컨텍스트·learnings 루프·Heartbeat) 커뮤니티에서 다운로드 → "start here" 명령 실행 → 당일 완전히 작동하는 비즈니스 OS 완성
    - 중요: 새 스킬 추가 시 자동으로 일관된 포맷으로 재정렬

*(이후 영상 끝까지 중요한 흐름이 바뀔 때마다 시간대별 요약 추가)*
