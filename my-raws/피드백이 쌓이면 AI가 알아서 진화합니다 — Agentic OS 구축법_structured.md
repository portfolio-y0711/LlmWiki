## 📝 1. 영상 전체 요약

> 개별 스킬을 따로 쓰는 것은 엑셀을 계산기로 쓰는 것과 같다는 문제의식에서 출발해, 공유 브랜드 컨텍스트·러닝스 루프·스킬 체이닝 세 요소를 하나의 프로젝트 폴더로 연결함으로써 피드백이 축적될수록 스스로 진화하는 Agentic OS를 구축하는 방법을 제시한다.

## 📖 2. 영상 주요 주제 (추상화된 목차)

*   **[문제 진단: 개별 스킬 사용의 3가지 한계]**

    - **세부 주제:** ① 스킬이 나를 모름: 범용으로 만들어진 외부 스킬은 브랜드 톤·타겟 고객을 모름. 매번 "우리는 캐주얼한 톤, 타겟은 30대 직장인"을 직접 설명해야 함 — 나한테 안 맞는 옷을 억지로 입는 느낌
    - **세부 주제:** ② 피드백이 사라짐: 같은 세션에서는 수정되지만 다음 세션에서 또 같은 실수를 반복. 같은 피드백을 두 번 세 번 반복
    - **세부 주제:** ③ 스킬이 연결 안 됨: 리서치 스킬 결과를 뉴스레터 스킬에 넘기려면 수동으로 복사·붙여넣기 필요. 스킬이 아무리 많아도 각각 따로 노는 구조

*   **[해결 구조: 프로젝트 폴더 + 공유 브랜드 컨텍스트]**

    - **세부 주제:** 폴더 구조: 프로젝트 폴더 안에 `CLAUDE.md`(전체 시스템 규칙) + `brand-context/`(브랜드 보이스·타겟 고객·포지셔닝) + `skills/`(개별 스킬들)
    - **세부 주제:** 공유 컨텍스트의 핵심: 모든 스킬이 같은 `brand-context/` 폴더를 참조. 뉴스레터 스킬이든 카피라이팅 스킬이든 같은 보이스 프로파일·타겟 고객 정보를 읽음. 한 번 정리하면 매번 설명 불필요 — 신입 직원한테 매번 설명하는 대신 온보딩 문서를 한 번 만들어 놓는 것

*   **[러닝스 루프: 피드백이 스킬을 진화시키는 구조]**

    - **세부 주제:** 3단계 루프: ① 스킬 실행 → 결과물 출력 → ② 사용자 피드백("너무 길어", "톤이 딱딱해") → `learnings.md`에 기록 → ③ 세션 종료 전 랩업 실행 → 누적 피드백을 스킬 MD 지침에 반영
    - **세부 주제:** `learnings.md` 구조: 스킬별로 섹션 분리 + 날짜 기반 피드백 누적. 예: 뉴스레터 스킬 섹션에 "3월 10일 — 분량 너무 길다. 800자 이내로", "3월 14일 — CTA는 하나만". 스킬별 분리 이유: "분량 줄여라"가 뉴스레터엔 맞지만 유튜브 대본엔 안 맞을 수 있음
    - **세부 주제:** 랩업(Wrap-up): 주기적으로 실행해 `learnings.md`의 누적 피드백을 읽고 스킬 MD 지침 자체를 업데이트. 예: "800자 이내"가 세 번 반복됐다면 스킬 MD에 "총 분량 800자 이내" 제약 추가 → 다음 실행부터 수정된 지침 자동 적용
    - **세부 주제:** 자동화의 전제: 피드백 기록은 저절로 되지 않음. `CLAUDE.md`에 "피드백이 오면 `learnings.md`에 기록해라"는 규칙을 명시해야 함 — 클로드는 지침을 따르는 것, 좋은 지침이 있으면 잘하고 없으면 못함

*   **[스킬 체이닝과 Agentic OS 완성]**

    - **세부 주제:** 스킬 체이닝: 한 스킬의 아웃풋이 다음 스킬의 인풋이 됨. 예: 트렌드 리서치 스킬이 Reddit·X에서 핫토픽 수집 → `research-brief.md` 저장 → 뉴스레터 스킬이 해당 파일을 입력으로 받아 브랜드 톤에 맞는 뉴스레터 작성
    - **세부 주제:** 시스템의 완성 형태: 모든 스킬이 공유 브랜드 컨텍스트를 참조 + 러닝스로 보정 + 체이닝으로 연결 → 일관성 있는 결과물. "개별 레고 블록이 아니라 레고 블록이 결합된 완성품"
    - **세부 주제:** 핵심 원칙: 프롬프트 하나 잘 쓰는 것이 중요한 게 아니라 프롬프트가 돌아가는 시스템을 설계하는 것이 중요. 한 번 만들고 끝이 아니라 쓸수록 나한테 맞게 진화하는 구조

*(참고: 이 항목은 영상의 논리적 구조를 추상화하여 그룹화한 것이며, 시간 정보는 포함되지 않습니다.)*

## ⏳ 3. 주요 시간대별 상세 요약

*   **[00:00:00] ~ 도입: 엑셀을 계산기로 쓰고 있다]**

    - 남의 스킬을 하나씩 따로 쓰는 것 = 엑셀을 계산기로 쓰는 것. 기능은 되지만 진짜 힘을 못 쓰고 있음
    - 개별 스킬의 3가지 문제: ① 브랜드 톤·타겟 고객을 모름 → 매번 직접 설명 ② 피드백이 저장 안 됨 → 같은 실수 반복 ③ 스킬이 연결 안 됨 → 결과물 수동 복사·붙여넣기

*   **[00:01:30] ~ 해결책: 하나의 프로젝트 폴더로 모으기]**

    - 폴더 구조: `CLAUDE.md`(시스템 규칙) + `brand-context/`(브랜드 보이스·타겟·포지셔닝) + `skills/`(스킬들)
    - 핵심: 모든 스킬이 같은 `brand-context/`를 참조 → 한 번 정리하면 매번 설명 불필요
    - 비유: 신입 직원한테 매번 회사 톤을 알려주는 게 아니라 온보딩 문서를 한 번 만들어 놓는 것

*   **[00:02:30] ~ 러닝스 루프: 피드백이 스킬을 진화시키는 구조]**

    - 3단계: 스킬 실행 → 피드백("너무 길어", "톤이 딱딱해") → `learnings.md`에 기록
    - 전제 조건: `CLAUDE.md`에 "피드백이 오면 `learnings.md`에 기록해라" 규칙 명시 필요. 자동으로 되지 않음 — 클로드는 지침을 따르는 것
    - `learnings.md` 구조: 스킬별 섹션 + 날짜 기반 누적. 뉴스레터 섹션: "3월 10일 — 800자 이내", "3월 14일 — CTA 하나만". 카피라이팅 섹션: "3월 12일 — 말줄임표 선호"

*   **[00:03:30] ~ 랩업: 피드백을 스킬 지침에 반영]**

    - 랩업(Wrap-up): 세션 종료 전 주기적으로 실행. `learnings.md`의 누적 피드백을 읽고 스킬 MD 지침 자체를 업데이트
    - 예시: 원래 스킬 MD에 "자유롭게 작성"이라고 되어 있었는데 "800자 이내"가 세 번 반복됐다면 → 스킬 MD에 "총 분량 800자 이내" 제약 자동 추가
    - 효과: 다음 실행 시 수정된 지침을 읽으므로 같은 피드백 반복 불필요. "랩업을 주기적으로 돌려야 하는 이유"

*   **[00:04:30] ~ 스킬 체이닝: 한 스킬의 아웃풋이 다음 스킬의 인풋]**

    - 예시 파이프라인: 트렌드 리서치 스킬(Reddit·X 핫토픽 수집 → `research-brief.md` 저장) → 뉴스레터 스킬(해당 파일 읽어 브랜드 톤에 맞는 뉴스레터 작성)
    - 완성 형태: 공유 브랜드 컨텍스트 참조 + 러닝스 보정 + 체이닝 연결 = 일관성 있는 결과물 자동 생성
    - "개별 레고 블록이 아니라 레고 블록이 결합된 완성품"

*   **[00:05:20] ~ 결론: 시스템 설계가 핵심]**

    - 핵심 원칙: 프롬프트 하나 잘 쓰는 것보다 프롬프트가 돌아가는 시스템을 설계하는 것이 중요
    - 쓸수록 나한테 맞게 진화하는 구조가 목표 — 한 번 만들고 끝이 아님
    - 실천 방법: 스킬을 따로 쓰지 말고 하나의 프로젝트에 모으고, 공유 컨텍스트 만들고, 피드백 축적 구조 세팅. 시작점: `CLAUDE.md` 하나 잘 쓰기

*(이후 영상 끝까지 중요한 흐름이 바뀔 때마다 시간대별 요약 추가)*
