## 📝 1. 영상 전체 요약

> Claude Code(Opus 4.7)와 Codex(GPT-5.5)에게 동일한 실시간 협업 마크다운 에디터(CollabMD)를 동일한 프롬프트 순서로 빌드하게 하여 속도·비용·완성도·코드 품질 4가지 기준으로 비교한 결과, Claude Code는 빠른 속도와 직접적 실행에, Codex는 자동 테스트와 검증 및 비용 효율에 강점이 있어 용도에 따라 병행 사용을 권장한다.

## 📖 2. 영상 주요 주제 (추상화된 목차)

*   **[실험 설계 및 평가 기준]**

    - **세부 주제:** 빌드 대상 앱 — CollabMD: 스플릿 페인 마크다운 에디터, 실시간 협업(WebSocket), 커서 프레즌스, 문서 관리, 자동 저장 등 포함한 복잡한 풀스택 앱
    - **세부 주제:** 공정한 비교를 위해 동일한 기술 스택 스펙 제공, 8단계 순차 프롬프트(스캐폴딩 → 에디터 → 실시간 동기화 → 커서 프레즌스 → 랜딩 페이지 → CRUD → 에러 핸들링 → 버전 히스토리/다크 모드) 사용
    - **세부 주제:** 사용 모델: Claude Code — Opus 4.7 Max Mode, Codex — GPT-5.5 Extra High (1.5x 속도 비활성화로 동등 조건 유지)

*   **[속도 비교]**

    - **세부 주제:** 대부분의 태스크에서 Claude Code가 Codex보다 50~70% 빠름. Phase 1 기준 Claude 6분 vs Codex 14분
    - **세부 주제:** Codex가 느린 이유 — 코드 작성 후 자동으로 브라우저를 실행하고 기능을 검증하는 컴퓨터 유즈(Computer Use) 단계를 추가로 수행
    - **세부 주제:** Claude Code는 코드만 작성하고 검증 없이 완료 처리 → 빠르지만 사용자가 직접 확인해야 하는 구조

*   **[완성도 및 기능 비교]**

    - **세부 주제:** Phase 1(스캐폴딩): Codex가 더 많은 디렉터리 구조와 타입 파일을 자동 생성. Claude는 최소한의 구조만 생성했지만 브라우저 실행 검증 미흡
    - **세부 주제:** Phase 3(실시간 협업): 두 도구 모두 WebSocket 기반 실시간 편집과 커서 프레즌스 구현 성공
    - **세부 주제:** 최종 결과물: 다크/라이트 모드, 마크다운·HTML 내보내기, 버전 히스토리, 실시간 커서, 공유 링크 등 기능 면에서 거의 동일한 완성도

*   **[코드 품질 비교]**

    - **세부 주제:** Claude Code — 모듈화는 어느 정도 되어 있으나, 컴포넌트 내 직접 API 호출, 과도한 인라인 코멘트, 복잡한 중첩 구조가 단점. 서버 코드는 단일 파일(200줄)에 집중
    - **세부 주제:** Codex — API 호출을 별도 파일로 분리, 타입 파일 별도 관리, 로그 파일 생성 등 구조적으로 더 정리됨. 클라이언트 코드 양도 상대적으로 적음
    - **세부 주제:** 상호 코드 리뷰: Codex가 Claude 코드 리뷰 시 fetch 패턴 문제 지적. Claude가 Codex 코드 리뷰 시 다수 이슈(키 입력마다 디스크 쓰기, 패치 전송, 오픈 테이블 등) 지적. 전반적으로 코드 품질은 비슷하나 Codex가 소폭 우세

*   **[비용 효율 및 최종 결론]**

    - **세부 주제:** 구독 소모량: Claude Code가 5시간 윈도우 기준 23% 소모, Codex는 5% 소모 → Claude가 약 2~2.5배 더 많은 구독 소모 (3~4배 비용 차이 추정)
    - **세부 주제:** Codex는 컨텍스트 창 한도 도달 시 자동 압축 수행(258k 토큰), 비용 효율적 운영
    - **세부 주제:** 최종 권장: 빠른 프로토타이핑·신규 프로젝트 스캐폴딩 → Claude Code / 디버깅·테스트·대형 프로젝트 유지보수 → Codex. 두 도구 병행 사용 권장

*(참고: 이 항목은 영상의 논리적 구조를 추상화하여 그룹화한 것이며, 시간 정보는 포함되지 않습니다.)*

## ⏳ 3. 주요 시간대별 상세 요약

*   **[00:00:00] ~ 영상 개요 및 실험 설계 소개**

    - Claude Code vs Codex 직접 비교 영상 소개. 평가 기준 4가지 제시: ① 속도, ② 비용(구독 소모량), ③ 완성된 결과물(버그 여부, 스펙 준수), ④ 코드 품질(상호 리뷰)
    - 빌드 대상: CollabMD — 스플릿 페인 마크다운 에디터, WebSocket 기반 실시간 협업, 커서 프레즌스, 문서 CRUD, 자동 저장, 버전 히스토리, 내보내기 기능 포함
    - 동일한 기술 스택 스펙 문서를 8단계 프롬프트로 분할하여 순서대로 전달하는 방식으로 진행

*   **[00:01:45] ~ 실험 환경 설정**

    - Claude Code: Opus 4.7, Max Mode, 풀 퍼미션 모드(bypass). Codex: GPT-5.5, Extra High, 1.5x 속도 비활성화
    - 시작 시점 구독 잔여량: Claude 5시간 윈도우 89% 남음, Codex 100% 남음

*   **[00:03:15] ~ Phase 1: 프로젝트 스캐폴딩**

    - 동시에 첫 번째 프롬프트 전달. Claude Code 약 6분 만에 완료. Codex는 14분 소요 — Codex가 브라우저 자동 실행·검증(Computer Use) 수행이 원인
    - 결과 비교: Codex는 types 파일, dist, data, logs 폴더 등 더 완성된 디렉터리 구조 생성. Claude는 최소 구조만 생성, 브라우저 프리뷰 없이 완료 처리
    - Codex는 새 문서 생성·렌더링 확인까지 자동으로 수행. Claude는 직접 실행 요청 후에야 앱 확인 가능

*   **[00:05:30] ~ Phase 2: 스플릿 스크린 에디터**

    - 두 번째 프롬프트(좌측 편집창 + 우측 미리보기 + 상단 바). 이번엔 비슷한 시간에 완료
    - Codex 버전(5174 포트): 무한 루프 버그 발생. Claude Code 버전: 새 문서 버튼 미작동 버그, /doc/test 경로 직접 접근 시 에디터 정상 동작 확인

*   **[00:07:00] ~ Phase 3: 실시간 협업 구현**

    - 실시간 WebSocket 동기화 추가. Codex가 7분으로 먼저 완료, Claude Code는 이후 완료
    - Codex 결과: 두 탭에서 실시간 편집 동기화 확인, 커서 식별자(User 83 등) 표시. Claude Code 결과: 커서 인텐트·하이라이트 동작, 문서 미저장 버그 발견

*   **[00:09:30] ~ Phase 4: 커서 프레즌스 및 코드 구조 검토**

    - 커서 프레즌스 상세 구현(연결 사용자 수·위치 표시). Claude Code가 약 1분 먼저 완료, Codex는 브라우저 테스트 자동 수행으로 추가 3~4분 소요
    - 코드 구조 비교: Claude — components/pages 구조, Tailwind 사용, async smoke.mjs 스크립트 포함, 서버는 src/db/index 구성. Codex — types/pages/lib/components 분리, API 호출 별도 파일, 로그 폴더 포함

*   **[00:12:00] ~ 최종 Phase(5~8 통합): 랜딩 페이지, CRUD, 버전 히스토리, 다크 모드**

    - 남은 모든 기능을 단일 프롬프트로 통합 전달. Codex 26분, Claude Code 7~8분 소요
    - Codex는 대부분의 시간을 자동 테스트·스타일 수정에 할애. Claude Code는 코드 작성 완료 후 즉시 종료
    - 최종 완성도: 두 앱 모두 다크/라이트 모드, 마크다운·HTML 내보내기, 실시간 커서, 버전 히스토리, 공유 링크 기능 구현. 기능 면에서 거의 동일

*   **[00:15:00] ~ 코드 품질 분석 및 상호 리뷰**

    - Claude Code 앱 코드: 인라인 코멘트 과다, 컴포넌트 내 fetch 직접 호출(비권장 패턴), 복잡한 중첩. 서버는 단일 200줄 파일. 모듈성은 적당한 수준
    - Codex 앱 코드: API 호출·presence·theme 각각 별도 파일, 타입 파일 분리, 더 간결한 클라이언트 코드. 로그 디렉터리, 데이터 폴더 별도 관리
    - 상호 리뷰 결과: Codex가 Claude 코드에서 fetch 패턴·퍼시스턴스 문제 지적. Claude가 Codex 코드에서 키스트로크마다 디스크 쓰기·패치 전송, 오픈 테이블 등 다수 이슈 발견

*   **[00:18:30] ~ 비용 비교 및 최종 결론**

    - 구독 소모: Claude 5시간 윈도우 23% → Codex 5% → Claude가 약 2~2.5배 더 소모. 비용 기준 약 3~4배 차이 추정
    - Codex는 컨텍스트 창 258k 도달 시 자동 압축 → 비용 효율적 장기 운영에 유리
    - 최종 권장: **Claude Code** = 빠른 프로토타이핑, 신규 프로젝트 스캐폴딩 / **Codex** = 디버깅, 검증, 대형 프로젝트 유지보수 → 두 도구 병행 사용 권장
