## 📝 1. 영상 전체 요약

> Anthropic Claude Code의 Head of Product Cat Wu가 Lenny's Podcast 60분 인터뷰에서 공개한 내용으로, 6개월짜리 기능을 하루 만에 출시하는 비결(PRD 폐기·역할 모호·Research Preview 브랜드)과 미션 기반 의사결정, AI 시대 PM의 핵심 역량(프로덕트 테이스트·현재 모델 기반 제품 설계)을 정리하고, 초지능 이전까지 인간이 우위를 가지는 영역(이해관계자 관리·EQ적 상식)과 그 한시성을 솔직하게 밝힌다.

## 📖 2. 영상 주요 주제 (추상화된 목차)

*   **[출시 속도의 실체: 90일 35개 기능]**

    - **세부 주제:** 2026년 1~3월 90일간 Anthropic이 출시한 기능 35개(모델·제품·Claude Code·엔터프라이즈·플랫폼 전체 합산). 평균 2.6일에 하나. Lenny's Podcast 진행자 평가: "이런 페이스는 본 적이 없다"
    - **세부 주제:** Cat Wu 발언: 과거엔 6개월~12개월 걸리던 기능이 지금은 하루~1개월로 단축. AI와 모델 능력 향상이 엔지니어링을 가속하면서 제품 타임라인이 압축됨

*   **[속도의 비결: 프로세스 제거 4가지 장치]**

    - **세부 주제:** ① PRD(제품 요구 사항 문서) 거의 폐기. 대신 매주 메트릭 리뷰(팀 전체가 숫자 공유)와 팀 원칙 문서(핵심 사용자 정의)로 대체. PM 결재 없이 누구든 결정 가능 → PM이 병목 제거
    - **세부 주제:** ② 역할 경계 해체. PM이 직접 코드 커밋, 디자이너가 프론트엔드 개발, 엔지니어가 PM 역할 수행. 디자이너 대부분이 프론트엔드 엔지니어 출신
    - **세부 주제:** ③ 채용 전략 변화. 코드 PM 대신 프로덕트 테이스트 있는 엔지니어를 우선 채용. Cat Wu 본인 포함 팀 PM 대부분이 엔지니어 출신이거나 현재도 코드 작성
    - **세부 주제:** ④ Research Preview 브랜드. 거의 모든 기능을 "Research Preview" 라벨로 출시 — "이건 실험이고 안 좋으면 사라질 수 있다"는 사전 약속. 팀 부담 감소 + 사용자 기대치 조정

*   **[프로세스 없이도 방향이 유지되는 이유: 미션 기반 의사결정]**

    - **세부 주제:** Cat Wu의 핵심 통찰: "프로세스를 없앨 수 있는 진짜 이유는 미션이 의사결정의 디폴트를 만들어 주기 때문." 우선순위 충돌 시 "어느 쪽이 미션에 더 가까운가"로 직결 → 회의·토론·정치 없이 결정
    - **세부 주제:** Anthropic 미션: 안전한 AGI를 인류에게 가져다주자. Cat Wu의 극단적 사고실험: "Claude Code가 실패해도 Anthropic 전체 미션이 성공하면 매우 행복할 것" — 제품보다 회사 미션이 위에 있다는 팀 전체 공유 가치관
    - **세부 주제:** 속도의 대가: 제품 일관성 희생. 같은 기능을 수행하는 기능이 2~3개 동시 존재 → "일관성을 시장에 위임" 전략. 사용자 피드백으로 정리

*   **[모델이 기능을 잡아먹는 현상]**

    - **세부 주제:** 새 모델이 나올 때마다 기존 기능 삭제. 예: 초기에 긴 작업 중 맥락 유실을 보완하기 위해 만든 to-do 리스트 기능 → 모델이 강해져 자동 처리 → 기능 제거. "빠르게 만들면 빠르게 지운다"
    - **세부 주제:** 안정성보다 시장 피드백 우선. 기능의 수명은 모델 능력에 종속됨

*   **[AI 시대 PM의 핵심 역량]**

    - **세부 주제:** 프로덕트 테이스트(제품 감각): "코드가 싸질수록 무엇을 만들지에 대한 판단이 더 가치 있어진다." 매일 수만 개의 GitHub 이슈 중 진짜 만들어야 할 것, 사용자가 가장 행복할 방식을 고르는 능력. 자격증이 아닌 실제 사용과 사용자 피드백 경험으로만 키워짐
    - **세부 주제:** 현재 모델 기반 제품 설계: "미래 슈퍼 AGI용 제품 만들기는 쉽다. 진짜 어려운 건 지금 모델의 능력을 최대로 끌어내는 제품을 만드는 것." AGI 과신(텍스트 박스만 남음)과 AGI 불신(6개월 후 쓸모없는 보수적 설계) 사이의 적정선 유지
    - **세부 주제:** 모델 업데이트마다 다이얼 재조정: 새 모델 출시 시 제품 설계 전략을 다시 교정. 모델 능력이 예상보다 좋으면 방향 전환, 나쁘면 또 전환. 정답 없는 작업 → 가장 희소한 PM 능력

*   **[인간이 아직 우위에 있는 영역과 그 한시성]**

    - **세부 주제:** 모델이 아직 제공하지 못하는 "상식(common sense)": ① 이해관계자 파악(누가 이 출시에 영향 받는지), ② 관계 구조(팀장 간 친소관계, 과거 갈등), ③ 개인 선호(보고 방식·소통 채널 선호), ④ EQ적 판단(누구에게 언제 어떤 방식으로 알려야 매끄럽게 굴러가는지)
    - **세부 주제:** Cat Wu의 솔직한 단서: "이것도 결국 모델이 더 잘하게 될 겁니다. 하지만 지금은 아직 사람 영역." → 현재의 우위, 연구적 우위가 아님. 살아남는 사람은 "이 자리를 차지한 사람"이 아닌 "갭이 어디로 옮겨가든 빠르게 따라가는 사람"

*(참고: 이 항목은 영상의 논리적 구조를 추상화하여 그룹화한 것이며, 시간 정보는 포함되지 않습니다.)*

## ⏳ 3. 주요 시간대별 상세 요약

*   **[00:00:00] ~ 도입: 기획서 없이 하루 만에 출시하는 팀**

    - 도발적 사실 3가지 제시: ① 기획서(PRD)를 거의 안 씀, ② 출시 주기 6개월 → 하루로 단축, ③ PM이 직접 코드 커밋
    - 영상 3가지 정리 예고: ① 어떻게 매일 출시하는가, ② AI 시대 PM의 역할 변화, ③ Claude를 가장 많이 쓰는 Claude 팀 PM이 보는 AI의 사람 대체 가능성

*   **[00:01:30] ~ 90일 35개 기능: 출시 속도의 실체**

    - 2026년 1~3월 Anthropic 전체 기능 출시 수: 35개. 평균 2.6일에 하나
    - Lenny's Podcast 진행자: "이런 페이스는 본 적 없다, 매일 메이저 기능이 나오고 있다"
    - Cat Wu 직접 발언: 과거엔 12개월 걸리던 기능이 지금은 1개월, 때로는 하루. AI와 모델 능력 향상이 엔지니어링을 가속

*   **[00:03:00] ~ 속도의 비결 ①: PRD 폐기와 대체 시스템**

    - PRD 없는 대신 두 가지로 운영: 매주 메트릭 리뷰(팀 전체 숫자 공유) + 팀 원칙 문서(핵심 사용자 정의)
    - 이 두 가지가 있으면 PM 결재 없이 누구든 결정 가능 → PM이 병목 안 됨

*   **[00:04:00] ~ 속도의 비결 ②③: 역할 해체 + 채용 전략**

    - 역할 경계 해체: PM이 직접 코드 커밋, 디자이너가 프론트엔드 개발, 디자이너 대부분 프론트엔드 엔지니어 출신
    - 채용 전략: 코드 PM 채용 줄이고 프로덕트 테이스트 있는 엔지니어를 더 많이 채용. Cat Wu 본인과 팀 PM 대부분 엔지니어 출신

*   **[00:05:00] ~ 속도의 비결 ④: Research Preview 브랜드**

    - 거의 모든 기능을 "Research Preview" 라벨로 출시. "이건 실험이고 안 좋으면 사라질 수 있다"고 사용자에게 미리 약속
    - 효과: 팀 부담 감소 + 사용자 기대치 조정 → 마음 편하게 빨리 출시 가능
    - 4가지 조합(PRD 폐기 + 역할 해체 + 코드 PM 채용 + Research Preview) → 6개월 → 하루

*   **[00:06:30] ~ 프로세스 없이 방향 유지: 미션 기반 의사결정**

    - Cat Wu의 핵심 답변: "프로세스를 없앨 수 있는 진짜 이유는 미션이 의사결정의 디폴트를 만들어 주기 때문"
    - Anthropic 미션: 안전한 AGI를 인류에게. 우선순위 충돌 시 "어느 쪽이 미션에 더 가까운가"로 직결
    - 극단적 사고실험(단서 있는 발언): "Claude Code가 실패해도 Anthropic 전체 미션이 성공하면 매우 행복할 것" — 제품보다 미션이 위, 팀 전체 공유 가치관

*   **[00:08:30] ~ 속도의 대가: 일관성 희생과 기능 삭제**

    - 속도의 대가: 제품 일관성. 같은 기능 2~3개 동시 존재, 베스트 프랙티스 불명확 → "일관성을 시장에 위임". 사용자가 직접 써보고 더 나은 것을 알려주면 정리
    - 모델이 기능을 잡아먹는 현상: 초기 to-do 리스트 기능 → 모델 강화로 자동 처리 → 기능 제거. "빠르게 만들면 빠르게 지운다." 안정성보다 시장 피드백 우선

*   **[00:10:30] ~ AI 시대 PM 역량 ①: 프로덕트 테이스트**

    - Cat Wu 직접 발언: "코드가 싸질수록 무엇을 만들지에 대한 판단이 더 가치 있어진다. 매일 수만 개의 GitHub 이슈 중 진짜 만들어야 할 것, 가장 즐거운 사용자 경험을 고르는 것이 PM의 핵심 일"
    - 이 능력은 학교·자격증으로 길러지지 않음. 수많은 사용자 피드백 관찰, 도구 직접 사용, 모델 한계를 손으로 익혀야 개발

*   **[00:12:00] ~ AI 시대 PM 역량 ②: 현재 모델 기반 제품 설계**

    - 가장 어려운 스킬: 1개월 후 제품이 어떻게 보여야 하는지 정의. AI 모델과 사용자 행동이 매달 변화
    - AGI 과신의 함정: 어차피 모델이 다 해준다고 판단 → 텍스트 박스만 남음 → 현재 모델은 그 수준이 아님 → 제품 실패
    - AGI 불신의 함정: 현재 모델만 보고 보수적 설계 → 6개월 후 모델이 발전하면 쓸모없어짐
    - Cat Wu의 핵심 발언: "미래 슈퍼 AGI용 제품을 만드는 건 쉽다. 진짜 어려운 건 지금 모델의 능력을 최대로 끌어내는 제품을 만드는 것." 새 모델마다 다이얼 재조정 필요

*   **[00:15:00] ~ 인간 우위 영역과 그 한시성**

    - Lenny 질문: "초지능 이전까지 인간이 계속 필요한 영역은 어디인가?"
    - Cat Wu 답변: 모델이 아직 제공하지 못하는 상식(common sense) 4가지 — ① 이해관계자 파악, ② 관계 구조(팀 간 친소·이전 갈등), ③ 개인 선호(보고 방식·소통 채널), ④ 소통 타이밍 판단. PM이 매일 하는 문서에 적히지 않은 인간 사회 운영 규칙
    - 솔직한 단서: "이것도 결국 모델이 더 잘하게 될 겁니다. 지금은 아직 사람 영역." → 현재의 우위, 영구적 우위 아님. 살아남는 사람 = "갭이 어디로 옮겨가든 빠르게 따라가는 사람"

*(이후 영상 끝까지 중요한 흐름이 바뀔 때마다 시간대별 요약 추가)*
