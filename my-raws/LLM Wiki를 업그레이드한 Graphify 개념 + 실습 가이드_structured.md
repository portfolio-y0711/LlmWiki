## ⏳ 3. 주요 시간대별 상세 요약

*   **[00:00:00] ~ LLM Wiki 복습 및 Graphify 등장 배경**

    - 이전 LLM Wiki 영상 이후 Graphify에 대한 문의가 많아 영상을 준비했으며, 발표자 본인도 처음 써보는 도구로 파악하는 데 약 4시간이 걸렸다고 언급
    - LLM Wiki의 기본 동작 방식 복습: Raw 폴더에 자료를 넣고 에이전트가 인제스트(ingest) → 위키화 → 쿼리 응답하는 구조
    - LLM Wiki의 단점으로 모든 처리를 에이전트가 담당하기 때문에 토큰 낭비가 심하다는 점이 이미 커뮤니티에서 지적되기 시작했다고 설명

*   **[00:01:10] ~ Graphify의 개념 및 하이브리드 전략 설명**

    - Graphify는 LLM Wiki의 컨셉은 유지하되, 앞단의 전처리만 기계적으로 수행하여 효율화를 꾀한 도구
    - AST(Abstract Syntax Tree) 이론을 적용해 전달된 지식을 LLM 토큰 없이 기계적으로 분석하고 뼈대를 추출
    - 추출된 뼈대를 에이전트가 보기 좋게 정리하여 전달하는 하이브리드 전략으로, 이후 병렬 작업으로 빠르게 처리

*   **[00:02:20] ~ 실습 준비 — 환경 세팅 및 폴더 구성**

    - 1단계: UV 패키지 관리자로 가상 환경 세팅 후 Graphify 패키지 설치 (`uv` 명령어 사용)
    - 2단계: 프로젝트 폴더(`lab-graphify-test`) 내에 `notes` 폴더를 만들고, 기존 LLM Wiki에서 사용하던 마크다운 파일들을 복사
    - Codex 실행 시 `--dangerously-bypass` 플래그를 사용하면 허가 요청이 줄어든다는 팁 공유

*   **[00:03:40] ~ Graphify 실행 및 처리 과정 관찰**

    - `$graphify ./notes` 명령으로 notes 폴더를 대상으로 작업 실행
    - 25개 마크다운 파일 처리에 약 5~6분 소요, 단어 5,000개 이상이라 추가 벤치마크도 같이 실행됨을 확인
    - 토큰 절약을 위해 GPT-4.1 대신 서브 에이전트로 GPT-4.1 Mini + Medium Effort 조합을 자동 선택하는 것을 확인 — 저가 요금제 사용자에게 특히 유용할 것이라고 언급
    - 작업 완료 후 약 5배의 토큰 절감률이 보고됨

*   **[00:06:00] ~ 결과물 확인 — graph.html 시각화**

    - `graphify-out` 폴더 내에 graph-report, graph.html, graph.json 세 가지 산출물 생성됨
    - graph.html을 열면 문서 간 연관성을 노드-엣지 형태로 인터랙티브하게 시각화하여 보여줌
    - 클릭을 통해 특정 노드의 연결 관계를 확인할 수 있으며, 참고용으로 활용 가능 (렌더링 일부 이슈 있음)

*   **[00:07:30] ~ Codex 연동 세팅 및 실제 질의 테스트**

    - `graphify codex install` 명령으로 Codex가 Graphify 결과물(지식 그래프) 기반으로만 답변하도록 CLAUDE.md에 섹션 추가
    - 실제 질의 테스트: "인스타그램 하드는 어떻게 만들어야 하지?" → Codex가 그래프를 탐색하여 사이즈·썸네일·안정성 등의 정보를 정확히 답변
    - LLM Wiki와 Graphify는 결합해서 쓰는 것이 아닌 완전히 별도의 도구임을 명확히 정리하며 마무리

*(이후 영상 끝까지 중요한 흐름이 바뀔 때마다 시간대별 요약 추가)*
