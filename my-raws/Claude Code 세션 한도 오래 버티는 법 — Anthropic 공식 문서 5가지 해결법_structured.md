## 📝 1. 영상 전체 요약

> Anthropic 공식 블로그의 세션 관리 가이드를 토대로, Claude Code 세션 한도에 걸리는 근본 원인(컨텍스트 오염·오토 콤팩션의 지연 발동)을 설명하고, 매 응답 후 선택 가능한 5가지 옵션(/rewind·/clear·/compact·서브 에이전트·Continue)의 상황별 사용 기준을 제시하여 동일한 구독으로 세션 수명을 극대화하는 방법을 정리한다.

---

## 📖 2. 영상 주요 주제 (추상화된 목차)

*   **[컨텍스트의 작동 원리와 오염 현상]**

    - **세부 주제:** 컨텍스트 창 = Claude가 한 번에 보는 전부. 시스템 프롬프트, 대화 이력, 읽은 파일, MCP 호출, 로드된 스킬 전부 포함. Claude는 매 메시지마다 처음부터 끝까지 재독 → 대화가 길어질수록 토큰 소모가 덧셈이 아닌 곱셈
    - **세부 주제:** 컨텍스트 오염(Context Rot): 공식 문서 수치 — 컨텍스트 256K에서 정보 검색도 92%, 1M에서 78%로 하락. 창이 커질수록 주의가 분산되어 이전 실수 반복, 파일 안 읽고 수정하는 현상 발생. "1M이 보험이지 목표가 아님"

*   **[오토 콤팩션의 한계]**

    - **세부 주제:** 오토 콤팩션: 컨텍스트 95% 도달 시 자동 요약으로 이력 교체. 문제: 모델이 가장 산만한 상태(컨텍스트 오염 심화 구간)에서 요약 실행
    - **세부 주제:** 공식 비유: "전날 밤에 짐 싸기 vs. 출근 5분 전에 짐 싸기". 오토 콤팩션 = 출근 5분 전 상황. 결론: 오토를 기다리면 안 되고 먼저 선재적으로 처리해야 함

*   **[5가지 선택지와 상황별 기준]**

    - **세부 주제:** ① Continue(컨티뉴): 기본값. 이전 컨텍스트 전부가 필요한 경우에만 사용. 대부분의 사용자가 이것만 사용해 한도 도달
    - **세부 주제:** ② /rewind: 특정 지점으로 돌아가 이후 이력 삭제(더블 ESC 가능). 잘못된 경로로 진행 중일 때 사용. "Summary from here" 옵션으로 인수인계 메시지 생성 가능
    - **세부 주제:** ③ /clear: 세션 전체 초기화. 완전히 다른 작업으로 전환 시 사용
    - **세부 주제:** ④ /compact: 대화를 요약본으로 교체. 힌트 첨부 가능(예: "/compact OS 리팩토링에 집중, 테스트 디버깅 내용 제외"). 오토 콤팩션보다 일찍, 모델이 맑을 때 수동 실행
    - **세부 주제:** ⑤ 서브 에이전트: 독립 컨텍스트를 가진 서브 에이전트에게 작업 위임 후 결과만 수신. 판단 기준: "이 작업의 중간 출력물을 나중에 또 볼 일이 있나?" — 결론만 필요하면 서브 에이전트

*   **[3가지 핵심 전략 실전 적용]**

    - **세부 주제:** /rewind 핵심: 실패한 시도·잘못된 코드·틀린 추론이 컨텍스트에 누적되면 지수적으로 쌓임. 리와인드로 실패 이후 전체 삭제 + "접근법 A는 쓰지 마" 힌트 추가 → 결과물 동일, 컨텍스트 청결 → 세션 수명 2~3배 연장
    - **세부 주제:** 프로액티브 /compact: 큰 작업 시작 전, 다음 단계가 예상되는 시점에 먼저 실행. 개인 기준 예시: 1M 모델에서 12%(약 120K) 도달 시 선제 실행. 힌트 없는 오토 콤팩션은 중요 내용 임의 삭제 위험
    - **세부 주제:** 서브 에이전트 적합 사례: 스펙 문서 구현 검증(통과/실패만 필요), 다른 레포 코드 흐름 요약, GitHub Pull Request 기반 문서 작성. 부적합 사례: 현재 코드 리팩토링(중간 과정 전부 확인 필요 → 메인에서 직접)

*   **[결론: 창 크기와 무관한 불변 원칙]**

    - **세부 주제:** 공식 문서 핵심 메시지: "컨텍스트 창이 커져도 규칙은 안 바뀌었다." 모델은 여전히 산만해지고, 세션은 여전히 끊어야 하고, 선택지는 여전히 5가지
    - **세부 주제:** 5가지 기준 요약: /rewind = 잘못 갔을 때 / /compact = 맞게 가다 무거워졌을 때 / 서브 에이전트 = 중간 과정 불필요 시 / /clear = 완전 새 작업 전환 시 / Continue = 나머지 전부 아닐 때

*(참고: 이 항목은 영상의 논리적 구조를 추상화하여 그룹화한 것이며, 시간 정보는 포함되지 않습니다.)*

## ⏳ 3. 주요 시간대별 상세 요약

*   **[00:00:00] ~ 도입: 세션 한도 문제와 공식 문서**

    - Claude Code 커뮤니티의 공통 불만: "5시간도 안 썼는데 세션 한도에 걸렸다"
    - Anthropic 공식 블로그에서 세션 관리·컨텍스트 사용법 가이드 공개. 핵심: 한도에 걸리는 이유는 컨텍스트 창이 작아서가 아니라 세션을 끊는 타이밍을 모르기 때문

*   **[00:01:00] ~ 컨텍스트 작동 원리: 덧셈이 아닌 곱셈**

    - 컨텍스트 창 구성: 시스템 프롬프트 + 대화 이력 + 읽은 파일 + MCP 호출 + 로드된 스킬
    - 핵심: Claude는 매 메시지마다 컨텍스트를 처음부터 끝까지 재독. 30번째 메시지 = 첫 메시지의 30배 토큰 처리. 같은 세션을 오래 끌수록 같은 질문에 더 비싼 토큰 소모

*   **[00:02:00] ~ 컨텍스트 오염(Context Rot) 현상**

    - Anthropic 공식 수치: 256K에서 정보 검색도 92% → 1M에서 78%로 하락. 창이 커진다고 더 잘 찾는 게 아니라 오히려 주의 분산
    - 컨텍스트 오염 증상: 이전 실수 반복, 파일 안 읽고 수정, 점점 산만해지는 응답
    - 결론: "1M 컨텍스트는 보험이지 목표가 아니다. 꽉 채울수록 품질은 내려간다"

*   **[00:03:30] ~ 오토 콤팩션의 한계**

    - 오토 콤팩션: 컨텍스트 95% 도달 시 자동 요약으로 이력 교체. 문제: 95%면 이미 컨텍스트 오염이 심한 구간 — 모델이 가장 산만할 때 요약 실행
    - 공식 비유: 전날 밤에 여유 있게 짐 싸기(목록 작성, 빠진 것 확인 가능) vs. 출근 5분 전 허겁지겁 싸기(충전기 빠뜨림). 오토 콤팩션 95% = 출근 5분 전
    - 결론: 오토를 기다리면 안 되고 먼저 선재적으로 처리해야 함

*   **[00:05:00] ~ 5가지 선택지 소개**

    - 공식 문서: 매 응답 이후 5가지 선택지 존재
    - ① Continue: 기본값. 이전 컨텍스트 전부 필요 시만 사용
    - ② /rewind(더블 ESC): 특정 지점으로 돌아가 이후 이력 전부 삭제. 잘못된 경로 진행 시
    - ③ /clear: 세션 전체 초기화. 완전히 다른 작업 전환 시
    - ④ /compact: 대화를 요약본으로 교체(힌트 첨부 가능). 오토 콤팩션의 수동 버전
    - ⑤ 서브 에이전트: 독립 컨텍스트 에이전트에 작업 위임, 결과만 수신
    - 한도에 걸리는 이유: 대부분의 사용자가 ①번 Continue만 사용

*   **[00:06:30] ~ 핵심 전략 1: /rewind — 실패의 흔적 삭제**

    - 문제 상황: 클로드가 잘못된 경로로 진행 후 "그게 안 됐어, 이걸 시도해봐" → 실패한 시도·잘못된 코드·틀린 추론이 컨텍스트에 누적 → 다음 응답부터 쓰레기까지 재독 → 지수적 토큰 낭비
    - /rewind 활용: 실패 시작 지점으로 돌아가 이후 전체 삭제 → 새 프롬프트에 "접근법 A는 쓰지 마, 이 모듈이 그걸 노출하지 않아" 힌트 추가 → 결과물 동일, 컨텍스트 청결
    - 실무팁: /rewind 메뉴의 "Summary from here" 옵션 → Claude가 여기까지 배운 것을 요약한 인수인계 메시지 생성. "실패에서 배운 건 남기고 실패의 흔적은 지우는 방식"
    - 효과: 세션 수명 2~3배 연장

*   **[00:08:30] ~ 핵심 전략 2: 프로액티브 /compact — 선제 압축**

    - 핵심 차이: 오토 콤팩션은 95%(모델이 가장 산만할 때) 발동 vs. 프로액티브는 모델이 아직 맑을 때 수동 실행
    - 힌트 첨부가 중요: `/compact OS 리팩토링에 집중, 테스트 디버깅 내용 제외` → 요약 시 무엇을 남기고 버릴지 사용자가 결정. 오토 콤팩션의 임의 삭제 방지
    - 개인 기준 예시: 1M 모델에서 약 12%(120K) 도달 시, 큰 작업 시작 전 선제 실행
    - 타이밍이 같은 /compact라도 결과물 품질이 완전히 달라짐

*   **[00:10:30] ~ 핵심 전략 3: 서브 에이전트 — 중간 과정 불필요 시**

    - 판단 기준 질문: "이 작업의 중간 출력물을 나중에 또 볼 일이 있나?" → 결론만 필요하면 무조건 서브 에이전트
    - 서브 에이전트 적합 사례:
      - "이 사양 문서대로 구현됐는지 검증해 줘" → 통과/실패만 필요
      - "다른 레포 읽고 OS 흐름 요약해 줘" → 그 레포 파일을 내 컨텍스트에 남길 이유 없음
      - "GitHub PR 보고 이 기능 문서 작성해 줘" → 문서만 필요
    - 서브 에이전트 부적합: "지금 보고 있는 코드 리팩토링해 줘" → 중간 과정 전부 확인 필요 → 메인에서 직접
    - 이 습관만으로 메인 세션 컨텍스트가 현저히 가벼워짐

*   **[00:12:30] ~ 결론: 창 크기와 무관한 5가지 기준**

    - 공식 문서 핵심 메시지: "컨텍스트 창이 커져도 규칙은 안 바뀌었다." 1M이 되면서 200K 시절의 습관을 놓아버린 것이 한도 도달의 실제 원인
    - 5가지 기준 요약: /rewind = 잘못 갔을 때 / /compact = 맞게 가다 무거워졌을 때 / 서브 에이전트 = 중간 과정 불필요 시 / /clear = 완전 새 작업 전환 시 / Continue = 나머지 전부 아닐 때
    - "이 다섯 개 기준만 머리에 박아두면 같은 Claude 구독으로 지금보다 확실히 오래 버팁니다"

*(이후 영상 끝까지 중요한 흐름이 바뀔 때마다 시간대별 요약 추가)*
