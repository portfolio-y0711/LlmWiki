## 📖 2. 영상 주요 주제 (추상화된 목차)

*   **도입 — 실전 작업 환경과 첫 접근법**

    - **세부 주제:** 음성 딕테이션으로 초기 프롬프트 작성 — 완벽한 사양보다 빠른 입력을 우선시하는 접근
    - **세부 주제:** Plan Mode 활성화 — 대규모 작업 시 코드 작성 전 반드시 계획을 먼저 세우는 원칙

*   **핵심 설정 — Rules 파일과 상태 표시줄 커스터마이징**

    - **세부 주제:** 사용자 메모리(Rules) 파일 — 43줄의 가벼운 설정으로 "극도로 간결하게, 문법보다 간결함을 우선"하는 최상위 규칙 적용
    - **세부 주제:** 계획 말미에 미해결 질문 목록 요청 — 실행 전 모호함을 제거하는 핵심 규칙
    - **세부 주제:** 상태 표시줄 커스터마이징 — 현재 레포·브랜치·스테이징 파일 수를 한눈에 확인

*   **핵심 워크플로우 — 멀티페이즈 계획과 실행**

    - **세부 주제:** Plan Mode에서 탐색(Explore 서브에이전트) → 명확화 질문 → 계획 생성 → 미해결 질문 답변 → 멀티페이즈 분해의 전체 흐름
    - **세부 주제:** 컨텍스트 창 모니터링 — `context` 명령으로 토큰 사용량을 주기적으로 확인하며 단계별 진행
    - **세부 주제:** Accept Edits 모드 전환 — 계획 완료 후 실행 단계에서는 공격적으로 자동 수락

*   **심화 전략 — GitHub Issue로 계획 보존 및 컨텍스트 이관**

    - **세부 주제:** 멀티페이즈 계획을 GitHub Issue로 저장 — 컨텍스트 창 밖의 영구 자산으로 보관하여 팀 협업·비동기 피드백 가능
    - **세부 주제:** 컨텍스트 초기화 후 GitHub Issue에서 계획 재로드 — "get GitHub issue #24 and enact phase 4"로 새 컨텍스트에서 끊김 없이 재개

*(참고: 이 항목은 영상의 논리적 구조를 추상화하여 그룹화한 것이며, 시간 정보는 포함되지 않습니다.)*

## ⏳ 3. 주요 시간대별 상세 요약

*   **[00:00:00] ~ 도입 — 실제 작업을 보여주는 이유**

    - CLI 커맨드 추가라는 실제 작업을 진행하면서 Claude Code 활용법을 라이브로 시연
    - "무엇을 만드는지보다 어떻게 만드는지가 중요" — 큰 피처는 단일 컨텍스트 창을 초과할 수 있음
    - 음성 딕테이션으로 초기 프롬프트 작성 후 **Plan Mode** 활성화 (Shift+Tab으로 토글)



*   **[00:01:30] ~ Plan Mode 실행 — 탐색과 명확화 질문**

    - Plan Mode: Explore 서브에이전트가 CLI 구조와 코드베이스를 먼저 탐색
    - Claude Code가 명확화 질문들을 순차적으로 제시:
      - "커밋 diff를 어느 레포 경로에서 가져올까?" → CLI 옵션으로 처리
      - "positional argument vs required option?" → required option 선택
      - "exercise 번호 매칭을 엄격하게 vs 유연하게?" → flexible 선택
      - "'01'이 무엇을 나타내는가?" → diff 시퀀스 번호
    - 모든 답변 후 초안 계획 생성



*   **[00:03:30] ~ Rules 파일 설정 공개**

    - `memory` 명령으로 사용자 메모리(Rules) 파일 접근 — 43줄의 가벼운 설정
    - **핵심 규칙들**:
      - "모든 상호작용과 커밋 메시지에서 **극도로 간결하게**, 문법보다 간결함 우선" → 계획이 읽기 쉽게 출력되는 이유
      - "각 계획 말미에 **미해결 질문 목록** 제공 (있는 경우)" → 실행 전 모호함 제거
      - "GitHub과 상호작용 시 GitHub CLI(`gh`) 사용"
      - "브랜치 생성 시 `matt-` 접두사 사용"
    - 상태 표시줄: 현재 레포명·브랜치·스테이징/언스테이징/신규 파일 수 표시



*   **[00:06:00] ~ 멀티페이즈 계획으로 전환**

    - 단일 계획으로는 컨텍스트 창을 초과할 것 같다는 직감 → "계획을 멀티페이즈로 분해해줘" 요청
    - 결과: 5개 페이즈로 분해된 구조화된 계획 생성
    - 컨텍스트 확인: 탐색 + 계획 단계 완료 후 83.7% 여유 (약 33k 토큰 사용)



*   **[00:08:00] ~ 페이즈별 실행 — Accept Edits 모드**

    - Plan Mode → **Accept Edits 모드** 전환 후 "execute phase one" 실행
    - Phase 1 완료 후 VS Code에서 변경사항 확인:
      - `get-diffs.ts` 신규 파일 추가 확인
      - Phase 2를 위한 TODO 주석이 코드에 남겨짐 → 다음 페이즈의 힌트
    - Phase 1: 약 3k 토큰만 추가 사용 → Phase 2·3 연속 실행
    - 자동 포매터로 파일 변경 발생 시 → Claude에게 명시적으로 알리고 파일 재로드 요청



*   **[00:11:00] ~ GitHub Issue로 계획 보존 및 컨텍스트 초기화**

    - Phase 4·5 남은 상태에서 컨텍스트 초기화 시연
    - "현재 계획 전체(완료된 항목 포함)를 GitHub Issue로 생성해줘" → `gh issue create` 실행
    - 컨텍스트 초기화 후 16k 토큰(메모리 파일·시스템 프롬프트만 남음)으로 리셋
    - 새 컨텍스트에서 "get GitHub issue #24 and enact phase 4" 단 한 줄로 재개
    - Issue를 미리 조회했으므로 Phase 5는 추가 조회 없이 바로 실행



*   **[00:14:00] ~ 마무리 — 핵심 3가지 팁 정리**

    - ① **Rules 파일에 "극도로 간결하게" 규칙 추가** — 가장 큰 효과를 본 단일 설정
    - ② **각 계획 말미에 미해결 질문 목록 요청** — 실행 전 모호함 사전 제거
    - ③ **GitHub CLI로 계획을 Issue에 저장** — 여러 컨텍스트 창 간 상태 공유 + 팀 협업·비동기 피드백 가능
