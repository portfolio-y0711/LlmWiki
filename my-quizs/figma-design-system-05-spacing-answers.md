## 1부. 객관식 정답

| 문제 | 정답 | 해설 |
|------|------|------|
| Q1 | **B** | 강의 정의: "spacing is the space between text, images, buttons and other interface elements that ensures visual harmony, readability and usability." — 요소 **사이의 공간**으로 시각적 조화·가독성·사용성을 보장하는 것입니다. |
| Q2 | **B** | 8포인트 시스템은 "기준 8px을 배수로 곱해 일관된 값들을 생성"하는 방식입니다. 단, FDS의 실제 값에는 8의 배수가 아닌 2, 4, 12도 포함되므로 A는 틀렸습니다. |
| Q3 | **B** | Input 컴포넌트 필드 내부: 수평 패딩 **16px**, 수직 패딩 **12px**. 강의에서 "16 pixel horizontal and 12 pixel vertical padding"이라고 명시했습니다. |
| Q4 | **C** | 강의에서 "side margins of **24 pixels** keep the content away from the edge of the screen"이라고 명시했습니다. |
| Q5 | **C** | T셔츠 사이징은 2XS(2px)부터 12XL(112px)까지 **17단계**입니다: 2·4·8·12·16·24·32·40·48·56·64·72·80·88·96·104·112. |
| Q6 | **D** | 스페이싱은 픽셀 수치 값이므로 **Number** 타입으로 생성합니다. Color, Boolean, String은 다른 용도의 변수 타입입니다. |
| Q7 | **B** | 카드 Container 패딩 → `space/L` **(16px)**, 콘텐츠 내부 간격(텍스트 간, 작성자 간) → `space/S` **(8px)**. 강의에서 직접 적용하는 과정을 보여줬습니다. |

## 2부. O / X 정답

| 문제 | 정답 | 해설 |
|------|------|------|
| Q8 | **X** | FDS의 스페이싱 값에는 **2, 4, 12**처럼 8의 배수가 아닌 값도 포함됩니다. 8포인트 시스템은 8을 기준으로 하되, 소수 단계(2, 4)와 중간 단계(12)도 포함합니다. |
| Q9 | **X** | 컬렉션 이름은 **"spacing"**, 그룹 이름은 **"space"**로 서로 다릅니다. 강의에서 컬렉션 생성 시 "spacing"을, 변수를 그룹으로 묶을 때 "space"를 사용했습니다. |
| Q10 | **O** | Dev Mode를 켜면 엔지니어가 적용된 스페이싱 변수와 값을 그대로 확인할 수 있습니다. 강의에서 "if you are an engineer have Dev mode I can turn that on and see the spacing variables"라고 직접 시연했습니다. |

## 3부. 빈칸 채우기 정답

**Q11.**
> 컬렉션 이름: **"spacing"**, 변수 타입: **Number**, 총 **17**개 생성, 첫 번째 변수 생성 후 **복제(Duplicate)** 방식으로 16번 복제해 나머지를 확보한다.

---

**Q12.**
> 가장 작은 단계: **2XS** (**2**px), 가장 큰 단계: **12XL** (**112**px). 전체 변수 그룹 이름: **"space"**.

---

**Q13.**
> - 헤딩 ↔ 본문 텍스트: **8**px
> - 본문 텍스트 ↔ 작성자 정보: **16**px
> - 아바타 ↔ 작성자 세부 정보: **8**px

---

## 4부. 단답형 정답

**Q14.**
> 첫 번째 변수(값: 2)를 Number 타입으로 생성한 뒤, **Duplicate(복제) 기능을 16번 반복**하여 총 17개를 한 번에 확보했습니다. 그 후 각 변수의 이름과 값을 순서대로 수정했습니다.

---

**Q15.**
> Input 컴포넌트에서 **8px**이 사용되는 위치:
> 1. **레이블 ↔ 필드** 사이 간격
> 2. **필드 ↔ 헬프텍스트** 사이 간격
> 3. 필드 내부 **텍스트 ↔ 에러 아이콘** 사이 간격
>
> *(강의: "between the label and the field is eight, between the field and help text is eight, in between the text itself and the icon we have eight")*

---

**Q16.**
> 스페이싱 레이어를 끄면 **화이트스페이스(여백)가 레이아웃 소비성(consumability)을 얼마나 높이는지**를 시각적으로 확인할 수 있습니다. 강의에서 "providing enough white space around each element has created a layout that makes the content easier to consume"이라고 설명하며 직접 토글 시연을 보여줬습니다.

## 5부. 서술형 모범 답안

**Q17. 8포인트 시스템 + T셔츠 사이징 구조의 실무적 이점**

> **구조 설명:**
> FDS의 스페이싱 스케일은 두 개념의 결합으로 이루어집니다. **8포인트 시스템**은 기준값 8px을 배수로 곱해 일관된 수치 집합을 만드는 방법론이고, **T셔츠 사이징**은 2XS·XS·S·M·L·XL·2XL~12XL 같은 의미 있는 이름으로 각 단계를 지칭하는 명명 체계입니다. 두 가지를 결합하면 `space/L = 16px`, `space/S = 8px`처럼 사람이 읽기 쉬운 이름과 예측 가능한 픽셀 값을 동시에 제공합니다. 실제 값은 2·4·8·12·16·24·32·40·48·56·64·72·80·88·96·104·112 총 17단계입니다.
>
> **디자이너에게의 이점:**
> `space/L`처럼 의미 기반 이름을 사용하면 "패딩이 16px인지 20px인지"가 아니라 "이 요소는 L 크기의 여백이 적절하다"는 판단으로 설계할 수 있습니다. 임의의 숫자 대신 시스템에서 허용된 값만 선택하게 되어 디자인 일관성이 자연스럽게 유지됩니다.
>
> **엔지니어에게의 이점:**
> Dev Mode에서 `space/L (16px)` 같은 변수명과 값을 그대로 확인할 수 있어, 디자이너와 엔지니어가 동일한 토큰 언어로 소통할 수 있습니다. 하드코딩된 픽셀값이 아닌 변수명 기반으로 구현하면 스케일 값이 바뀌어도 코드 수정이 한 곳에서 가능합니다.

---

**Q18. 컴포넌트·카드·화면 레벨별 스페이싱 분석**

> **컴포넌트 레벨 (Input):**
> - 레이블 ↔ 필드: 8px / 필드 ↔ 헬프텍스트: 8px
> - 필드 내부 수평 패딩: 16px / 수직 패딩: 12px
> - 텍스트 ↔ 에러 아이콘: 8px
> → 컴포넌트 레벨은 **작은 단위의 관계(8px 위주)**를 정밀하게 제어하는 것이 특징입니다.
>
> **카드 레벨:**
> - 전체 패딩: 16px
> - 헤딩 ↔ 텍스트: 8px / 텍스트 ↔ 작성자 정보: 16px
> - 아바타 ↔ 작성자 세부정보: 8px
> → 카드 레벨은 **외부 컨테이너(16px)와 내부 요소(8px)를 구분**하여 위계를 만드는 것이 특징입니다.
>
> **화면 레벨 (앱 스크린):**
> - 사이드 마진: 24px / 콘텐츠 블록 간격: 16px / 헤딩 ↔ 텍스트: 8px
> → 화면 레벨은 **가장 큰 단위의 여백(24px)**으로 콘텐츠를 화면 경계에서 보호하는 것이 특징입니다.
>
> **패턴 분석:**
> 세 레벨에서 공통적으로 발견되는 패턴은 **8 → 16 → 24**의 계층 구조입니다. 요소 내부의 최소 단위 간격에는 8px, 컨테이너 수준의 여백에는 16px, 화면 경계의 마진에는 24px이 반복적으로 사용됩니다. 이는 스케일이 올라갈수록 더 큰 스페이싱을 적용하는 원칙으로, 시각적 위계와 숨 쉬는 공간을 자연스럽게 만들어냅니다.

- **10점**: 핵심 개념 2가지 이상 + 구체적 수치/예시 + 이유/맥락 포함
- **7점**: 핵심 개념은 맞으나 수치나 예시가 부족하거나 한 가지 관점 누락
