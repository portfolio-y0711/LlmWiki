# ✅ 정답지: Figma Design System 02 — Primitive Color Variables

> 퀴즈 파일: `figma-design-system-02-primitive-color-variables-quiz.md`

---

## 1부. 객관식 정답

| 문제 | 정답 | 해설 |
|------|------|------|
| Q1 | **B** | Primitive 색상은 Blue, Red, Green 같은 **베이스 Hue**로, 디자인 시스템의 기본 색상 팔레트를 구성합니다. 디자이너가 직접 사용하는 색상이 아닌, Semantic 변수의 기반이 됩니다. |
| Q2 | **C** | FDS는 Brand·Blue·Purple·Violet·Red·Pink·Orange·Yellow·Green·Teal·Cyan·Black·White **총 13가지** Primitive 색상을 사용합니다. |
| Q3 | **B** | Tint는 기본 색상의 **명도(Lightness)를 높여** 밝게, Shade는 **명도를 낮춰** 어둡게 만듭니다. 채도나 색상 값이 아닌 명도를 조정하는 것이 핵심입니다. |
| Q4 | **C** | Neutral은 **Black 기반의 19단계** 스케일로, 다른 색상처럼 플러그인으로 생성하는 것이 아니라 **스타터 파일에 이미 플래트닝된 값(00~F2)**을 그대로 사용합니다. |
| Q5 | **C** | 네이밍 컨벤션은 **`color/shade`** 형식입니다 (예: `blue/500`, `pink/100`). Figma의 슬래시(`/`) 구조는 그룹 계층을 나타냅니다. |
| Q6 | **B** | **Styler 플러그인**은 선택된 색상 프레임들을 **Color Styles로 일괄 변환**합니다. 그 이후 "Styles to Variables" 플러그인이 이 Color Styles를 Variables로 변환합니다. |
| Q7 | **C** | Primitive를 숨기는 이유는 디자이너가 Semantic 변수만 사용하도록 유도하여 **색상 적용의 확장성** 확보와 **Figma 네이티브 라이트/다크 모드 전환**을 지원하기 위해서입니다. |

## 2부. O / X 정답

| 문제 | 정답 | 해설 |
|------|------|------|
| Q8 | **O** | 수동 방법은 정확히 이 방법입니다. 흰색과 검정을 20%, 40%, 60%, 80% 불투명도로 각각 오버레이 → 플래트닝 → 색상값 추출. 단, 강의에서 "Who's got time for that?"이라고 언급했듯이 매우 비효율적입니다. |
| Q9 | **X** | Variables 생성이 완료되면 기존 Color Styles는 **즉시 삭제**합니다. 강의에서 "You can now delete the Styles as they are no longer needed"라고 명확히 언급했습니다. |
| Q10 | **X** | **반대**입니다. **Brand가 최상단**, **Neutral이 최하단**에 위치합니다. "Reverse Layer Order" 플러그인을 사용해 정렬한 뒤, Brand를 최상단으로, Neutral을 Brand 바로 아래(Cyan 이후)에 배치합니다. |

## 3부. 빈칸 채우기 정답

**Q11.**
> FDS의 Primitive 색상은 총 **13**가지이며, Brand를 포함해 Blue, Purple, Violet, Red, Pink, Orange, Yellow, Green, Teal, Cyan, **Black**, **White**로 구성된다.

---

**Q12.**
> 먼저 **Styler** 플러그인으로 Color Styles를 생성하고, 그 다음 **Styles to Variables** 플러그인으로 해당 Color Styles를 "Primitives" 컬렉션의 Variables로 변환한다.
>
> *참고: 이 2단계 워크플로우로 총 118개 Color Style이 Primitives 컬렉션 변수로 변환됩니다.*

---

**Q13.**
> 색상 스케일 사이의 간격은 **32**px로 설정하며, Edit Variables → "**Hide from Publishing**" 옵션을 설정하여 디자이너에게 직접 노출되지 않도록 한다.

---

## 4부. 단답형 정답

**Q14.**
> 플러그인에 입력해야 하는 값은 해당 색상의 **Hex 값(16진수 색상 코드)**입니다.
> 색상을 선택 → 플러그인 실행 → Hex 값 입력 → Generate 버튼 클릭으로 9단계 스케일이 자동 생성됩니다.

---

**Q15.**
> **브랜드 색상**은 브랜드의 **주 Accent 색상(Primary Color)**입니다.
>
> 나머지 색상들의 색조 통일감을 위해, 브랜드 컬러를 기준으로 나머지 색상들의 **Hue(색상), Saturation(채도), Lightness(명도) 값을 조정**하여 전체적으로 통일된 톤을 가진 색상 세트를 구성했습니다.

---

**Q16.**
> 강의에서 언급된 정보:
> 1. **변수명(Variable Name)**
> 2. **Hex 값**
> 3. **RGBA 값**
> 4. **HSL 값** (강의에서 RGB 대신 HSL을 켜는 과정 언급)
>
> *참고: 정답으로 셋 중 임의 3가지를 기술해도 정답 인정*

## 5부. 서술형 모범 답안

**Q17. Primitive 숨기기와 Semantic 변수 분리의 중요성**

> **Variables 삭제가 가능한 이유:**
> 캔버스의 색상 프레임은 Variables 생성을 위한 중간 단계일 뿐, 일단 "Primitives" 컬렉션이 Variables 패널에 저장되면 원본 프레임은 필요 없어집니다. Variables는 Figma 파일 내 독립적으로 저장되므로, 캔버스에서 삭제해도 변수 데이터는 유지됩니다.
>
> **Semantic 변수만 노출하는 이유:**
> Primitive 변수를 "Hide from Publishing"으로 숨기고 Semantic 변수만 노출하면 두 가지 핵심 이점이 생깁니다. 첫째, **색상 적용의 확장성**: 디자이너가 의미 기반 색상(예: `primary`, `error`)을 사용하면, 나중에 브랜드 색상이 바뀌어도 Semantic 변수의 참조값만 수정하면 전체 UI에 자동 반영됩니다. 직접 Primitive 색상을 사용했다면 수백 개의 컴포넌트를 일일이 수정해야 합니다. 둘째, **네이티브 라이트/다크 모드**: Semantic 변수는 모드별로 다른 Primitive를 참조할 수 있어, Figma 내에서 한 번의 클릭으로 라이트/다크 모드 전환이 가능합니다.

---

**Q18. 수동 방법 vs 플러그인, 그리고 Neutral 스케일의 특수성**

> **수동 생성 방법:**
> 기본 색상 레이어 위에 흰색 레이어를 20%, 40%, 60%, 80% 불투명도로 오버레이하여 Tint 4단계를 만들고, 검정 레이어를 같은 방식으로 오버레이하여 Shade 4단계를 만든 뒤, 각각 플래트닝(합치기)하고 색상값을 하나씩 직접 추출해야 합니다. 정확한 결과를 얻을 수 있지만 색상 수가 많을수록 매우 비효율적입니다.
>
> **플러그인 방법 ("Color Tint & Shade Generator"):**
> 색상을 선택하고 Hex 값을 입력한 뒤 Generate 버튼 하나로 동일한 결과를 즉시 자동 생성합니다. 수동 방법과 동일한 품질이지만 시간이 대폭 단축됩니다. 단, 색상마다 Hex 값을 새로 입력해야 하는 번거로움이 있습니다.
>
> **Neutral 스케일의 차이점:**
> - **단계 수**: 다른 색상은 9단계(100~900)이지만, Neutral은 **19단계**입니다.
> - **출처**: 플러그인으로 생성하지 않고 **스타터 파일에 이미 준비된 값**을 사용합니다.
> - **범위**: `00`부터 `F2`까지의 범위로, Black 기반으로 사전에 플래트닝 처리된 값입니다.
> - **생성 후 처리**: 다른 색상 스케일과 함께 그룹화하여 관리합니다.

### 서술형 부분 채점 기준 (각 10점)
- **10점**: 핵심 개념 2가지 이상 정확히 서술 + 이유/맥락 설명 포함
- **7점**: 핵심 개념은 맞으나 이유 설명이 부족하거나 일부 누락
- **4점**: 부분적으로 정확하나 핵심 내용 절반 이상 누락
- **0점**: 내용이 틀리거나 학습 자료에 없는 내용 기술

### 점수대별 평가 기준
- **90점 이상** 🏆 — 강좌 내용을 완벽하게 이해했습니다!
- **70~89점** 👍 — 핵심 개념은 잡혔습니다. 놓친 부분을 다시 확인해보세요.
- **50~69점** 📖 — 강좌를 한 번 더 보고 구조를 다시 정리해보세요.
- **50점 미만** 🔄 — 강좌를 처음부터 다시 시청하는 것을 추천합니다.
